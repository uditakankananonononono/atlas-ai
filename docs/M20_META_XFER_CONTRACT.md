# META-XFER: bounded demonstrated policy transfer

Targets row11 Meta-Learning Across Domains for bounded SCOPED acceptance, PARTIAL
until independent acceptance. Existing MetaLearner role-sequence retrieval remains
unchanged. New explicit tenant SQL-bound TransferLearner stores demonstrated
problem/strategy records through META-DUR's staged CAS snapshots (kind meta_transfer).
Routes `/api/v1/api/modules/20/meta-transfer/learn` and `/transfer` require a bound
learner matching authenticated tenant. Restart reloads records; stale writers
refuse409, failed writes do not publish memory. SQLite acceptance, no PG claim.

Two declared task shapes only. Precedence_safe_completion validates a supplied
successful execution and adapts a fixed dependency-order strategy: this is a
structural baseline, NOT learned policy. Dependency_safe_setup_continuity induces
one of two declared policies by comparing its predicted execution order against
the observed successful order: lexical-ready-first or prefer-previous-group then
lexical. It accepts only a unique exact match; unsupported or ambiguous
observations abstain, rather than pretending to discover an open-world strategy.
Mismatch counts measure fit of explicit candidate policies, not confidence,
probability or truth. No arbitrary objective discovery or model training.

Demonstrated execution must visit every declared task once in dependency order;
failed episodes excluded, same ID exact duplicate idempotent, changed evidence
refuses. Provenance is retained caller evidence identifier, not independently
verified source identity/outcome. No independent real-world successful execution
claim. Explicit domain labels, not lexical-token similarity, enforce disjoint
transfer. Target graph and group labels map the policy into different actual task
names/dependencies and produce a plan candidate with source trace/preconditions/
invariants; no execution authorization is created. Same-domain, unsupported/cyclic
mapping and missing groups abstain. All effects remain behind normal approvals.

Held-out declared publishing/deployment/construction/travel/manufacturing fixtures
compare against copied source order/no-transfer and generic lexical topological
baselines. Learned grouping policy reduces declared setup-switch cost while
preserving target dependencies. Changing the demonstrated policy changes target
plan, proving more than retrieval/fixed-sort alone. This is conditional evidence
for these synthetic task families, not guaranteed target success or generalization.

Bounds: tasks1..64, dependency edges1..256, declared unique labels, no self/cycles,
128 source records/tenant, bounded strings, one whole-state snapshot. Direct public
patterns mutation can bypass durability; use learn. Policy family selection is
one successful demonstration, not statistical confidence. No model/provider/spend,
external retrieval/execution, hidden chain-of-thought, or other row closure.
Residual: only declared policy families/task shapes/tested domain mappings;
no general cross-domain learning/open-world acquisition/success guarantee.
