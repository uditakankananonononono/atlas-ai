# Claire owner interview - narrow tested slice

`PUT /api/v1/claire/interview/consent` with `{"enabled":true}` starts collection for the authenticated tenant and actor. `GET /next` returns one unanswered fixed question at a time; `POST /answers` accepts its exact choice, the owner's stated reason, and a reference to the source of that answer. `GET /context` returns only active answers while consent is on. `DELETE /answers/{id}` revokes an answer before a correction; `DELETE /answers` erases active and revoked answers. Disabling consent stops collection and hides answers from context, but does not erase them.

This adapts the separate Meemee personal-model idea of owner-scoped, evidence-referenced records to Claire's existing SQL backend. It does not import Meemee's SQLite store, its API, or any user's actual data. The client must supply an honest source reference; the route cannot authenticate an arbitrary reference by itself, so references are owner-reported until checked against their source. No preference is permission to send, apply, purchase, or operate an external account.

The bank has five fixed questions about evidence, outreach preparation, competition fit, uncertainty, and project workflow. It is not a model of the owner's intelligence. Questions do not dynamically inspect her documents; live document grounding and social scanning remain separate work. This slice has no autonomous side effects and no new paid dependency. An authenticated launch UI is not built yet. The direct tests cover consent, persistence, actor/tenant isolation, exact choices, correction, deletion and no-effect semantics. Three interview tests, including an authenticated API isolation check, and 59 adjacent Claire tests passed on Python 3.12 (62 targeted). The full suite has not been rerun here.
