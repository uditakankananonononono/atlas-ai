### WIP29 revision of the m22 discovery error handling
- Errors are call-local (Service.discover_report returns {ranked, errors, sources_attempted, sources_ok, sources_failed}); self.last_errors is only a last-writer-wins convenience copy. The route no longer reads shared state for real services (test doubles without discover_report fall back to it, best effort).
- Returned/logged errors are a bounded category per source (cooldown, timeout, network_unreachable, http_error, source_failed), never raw exception text (URLs, queries, IPs, credentials). At most 12 sources are listed in the 502 body. The header is valid JSON: counts + at most 5 shown + omitted count (never a sliced string).
- 502 only when every attempted source failed. A genuinely empty answer from a source that worked with others failing is 201 [] plus the header. Zero collectors/zero errors is a plain empty 201.
- A run with any failed or cooling-down source no longer commits a query snapshot, diff "removed" list or history entry (it records last_diffs[query] = {incomplete: true, failed_sources}); previously a failed run could record "all earlier candidates disappeared". Complete runs commit as before.
- Still open: Service/get_service in routes.py is a process-global shared discovery service (candidates cache, snapshots, cooldowns shared across tenants); persisted candidates are per-tenant in the pipeline DB, but the in-memory service state is not tenant-scoped. Not changed here.

### WIP30: m22 tenant scoping, legacy fallback removed
- Discovery Service is per tenant (routes.service_for_tenant; cap 64, 503 at cap, no eviction, in-memory, lost on restart). Per-tenant: candidate cache, query snapshots/history/diffs, cooldowns, source stats, blocklist. Shared on purpose: the collector objects (public registry data caches only, e.g. PyPI name index). Still NOT proven/changed: core approvals store (app.core.approvals) is shared by Service; production tenant auth unproven (dev headers = test mode); multi-worker inconsistency unproven.
- The racy last_errors fallback was removed: a discovery service without discover_report is unsupported (route raises). Error text is a coarse HEURISTIC category (substring classification of the exception text), not a diagnosis. An unhealthy source leaves an explicit incomplete diff state (last_diffs[q].incomplete) and commits no snapshot until a complete run succeeds.
