# M19 explicit immutable ranking snapshots

This unit captures what the current ranking saw, not what existed at an earlier date. A captured record preserves full included and full excluded visited rows, the ranked result, exact parameters, tenant, requesting actor, tenant revision, server captured_at, configured scoring code version, schema_version1 and a content checksum. census_scope is visited_rows_only; terminal-filtered ideas' evidence is not fetched. No decision replay or complete census is claimed.

Explicit authenticated owner POST /idea-incubator/portfolio/ranking-snapshots captures. GET /{snapshot_id} reads the same immutable record, GET /{snapshot_id}/compare separately labels the current_filter and compares full included-row hashes, POST /find resolves the latest exact-parameter snapshot or snapshot_available=false. Foreign tenants and other actors get the same404 as missing records. No GET captures, no automatic backfill/genesis, no application update/delete method. Reads validate schema version, row/payload identity and checksum. The existing /ranking/as-of remains a current timestamp filter, not an archive.

Capture requires PostgreSQL REPEATABLE READ. SQLite and unsupported dialects refuse capture; existing live ranking stays available. All source reads and insertion share one transaction. A tenant counter row lock allocates monotonically increasing revisions, helps coordinate capacity and concurrent capture; REPEATABLE READ serialization retry plus the unique tenant/revision constraint are also required; PostgreSQL serialization conflicts retry a maximum of three transactions, then require an explicit retry. No records are deleted to make space. Limits default4000000bytes per full canonical record including checksum and1000records/tenant; service configuration can only lower either limit. A failed or oversize capture rolls back its counter reservation and writes no record.

ATLAS_CODE_VERSION must be explicitly configured for the default capture route. Absence returns503 for capture, reads, find and compare through the default service factory, never a fabricated code SHA. Direct service tests inject a test version. Unknown/null JSON values survive as null; existing typed row schemas and required SQL fields remain enforced, rather than substituting the as_of date for missing timestamps. Unknown snapshot schema versions are refused. Default stale-experiment policy is exclude; current explicitly retains its caveat. Hash is only an internal checksum, not a signature, tamper-proof store, anti-rollback or nonrewindable authority. A trusted DB writer can fabricate a consistent payload or delete it; no key custody is added.

Migration20261010_m19_rank_snapshots chains after20261010_m14_wave_supersede and creates empty tables. Single head verified; fresh PostgreSQL empty->head, down-one and re-upgrade passed, with direct empty-table up/down tests. No source idea/evidence data rewritten.
