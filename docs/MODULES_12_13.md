# Modules 12 and 13

Module 12 adds a capability/cost/latency/quality router, validated YAML DAGs, concurrent ready-node execution, declared dependency passing, bounded retries, log-prob confidence, fallback models, and self-critique. Bind its model provider and Celery-backed node runner in application dependency overrides.

Module 13 adds Playwright session contexts, HAR recording, navigate/fill/screenshot/extract routes, heuristic form matching, an allow-listed VLM loop with a hard step cap, public-network URL validation, durable tenant-scoped audit records, and Module 0 approval requests. Submit approval binds tenant, session, selector, exact form-value digest, and screenshot. Changed content, denied/pending approvals, or reused approvals fail closed.

The opportunity application workflow (`m13_browser_agent.application_flow`, mounted via Module 2 under `/api/v1/competition-manager/applications`) runs the full apply journey end to end: create a tenant-isolated persistent paired session at an opportunity's official application URL; pause with `awaiting_user_login` plus owner-visible paired-browser instructions when the site requires authentication (Atlas never accepts, stores, or transmits passwords, MFA codes, cookies, or tokens - credential-shaped payload keys are rejected); resume only on explicit owner confirmation after the owner logs in themselves; extract form descriptors grounded in the page's own HTML; stage only owner-approved one-to-one matched fields (password inputs are never filled); read back exact on-page values; capture full-page screenshots with filled fields masked; and create a separate final-submit approval bound to tenant, actor, session, final URL, selector, exact values hash, and screenshot hash. Execution re-verifies every bound fact, consumes the approval atomically before the click (exactly once, no replay), and treats CAPTCHA, missing selectors (site redesign), navigation drift, and click failure as honest blocked/failed states - Module 2 status evidence is written only from the post-submit source readback. Sessions persist in `m13_application_sessions`; every navigation, login transition, inspect, fill, readback, screenshot, approval, and submit lands in the audit trail.

Production setup: add PyYAML and Playwright, install Chromium, start/close `PlaywrightSessions` in FastAPI lifespan, and configure an explicit host allow-list. Persistent sessions default off and the caller may enable them only for legally permitted sites. Store HAR/screenshots in tenant-isolated object storage with retention and redaction.
