# Module self-improvement engine

Every Atlas module (M00-M25) can now extend itself: it detects its own
capability gaps, synthesizes a new feature as real Python code, writes and
runs tests for it in a sandbox, and - only after a human approves through
the approval gate - activates it into its own feature registry.

## Pipeline

1. **Report** - module code (or the API) records a gap event:
   `engine.record_gap("filter only biology grants", exemplar=...)`.
   Events persist as append-only JSONL under the state dir.
2. **Detect** - `GapDetector` aggregates events by signature; a signature
   becomes a `CapabilityGap` at `min_occurrences` (default 2).
3. **Plan** - `FeaturePlanner` maps the gap to one of six capability kinds
   (`keyword_filter`, `scoring_rule`, `text_transform`, `aggregator`,
   `threshold_alert`, `field_extractor`) and fills parameters from the gap
   text. An optional `ProposalRefiner` (e.g. the shared local model layer)
   can enrich plans; the kind whitelist cannot be widened by a refiner.
4. **Synthesize** - `codegen` renders deterministic template code, and
   `testsynth` renders a pytest suite. Every generated byte passes the
   static safety scanner (`safety.validate_source`): import allowlist, no
   exec/eval/open, no dunder tricks, no async.
5. **Evaluate** - `SandboxRunner` executes the tests in a subprocess with a
   scrubbed environment and a hard timeout. Failing candidates die here.
6. **Propose** - passing candidates are persisted (with sha256) and an
   approval request is filed through the gate (`ManualApprovalGate`
   offline, `M00ApprovalGate` in production via Module 0).
7. **Activate** - only with an approved decision matching the candidate's
   own approval id. The feature file is copied into the module's
   `extensions/` dir and recorded in `registry.json`.
8. **Dispatch** - `engine.dispatch(name, items)` re-verifies the file's
   sha256 on every call; tampered features refuse to run.
9. **Rollback** - approval-gated; restores the previous active version.

## Autonomy boundary

Detection, planning, code writing, and testing are autonomous. Activation
and rollback are human-gated, consistent with the Approval Center (M00) and
the M20 SelfImprovementLab pattern. The engine never touches module source
code, safety rules, or the approval gate itself - features live only in the
module's own state directory.

## API

Mounted at `/api/v1/self-improve` (tenant-gated):

- `GET /{slug}/status`
- `POST /{slug}/gaps` - report a capability gap
- `POST /{slug}/cycle` - run one autonomous improvement cycle
- `POST /{slug}/candidates/{key}/activate` - with an approval id
- `POST /{slug}/features/{name}/rollback`
- `POST /{slug}/features/{name}/dispatch`

## Configuration

- `ATLAS_SELF_IMPROVE_HOME` - state root (default `~/.atlas/self_improve`)
- Free-first: no model, network, or paid API required anywhere in the loop.

## Tests

`tests/self_improve/` - 35 tests covering detection, planning, codegen,
safety scanning, sandboxing, registry integrity, the full engine cycle,
the mixin, wiring across all 26 catalog modules, and the HTTP surface.
