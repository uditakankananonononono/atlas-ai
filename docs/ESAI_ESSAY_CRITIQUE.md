# Student-authored essay critique (scoped, unaudited)
POST /api/v1/study-abroad/essay-tools/critique {draft} (tenant-authenticated like the other m23 routes).
- Coaching only. The response never contains rewritten text: generated_essay_prose and revised_draft are null; every item has an EXACT quote of the student's draft; question text comes from fixed templates or our own measure wording.
- verified_measure items (always on, deterministic, no model): sentences over 40 words (word count shown), a content word used 4+ times (count shown), a trait sentence ("passionate", "hard worker" ...) with no digit and under 25 words (the trait word shown).
- model_selected_span items: a local model (loopback only, no redirects, no env proxy, 12s budget, 2 slots) picks up to 2 phrases + a type (scene/evidence/reason/change); phrases must be exact copies of the draft or are rejected; the question is our template. Span choice and type fit are NOT verified (e.g. the "evidence ... shows this" template is a poor fit for a plain event).
- mode labels: model_selected_spans_plus_verified_measures / verified_measures_only_model_spans_rejected / verified_measures_only_no_model (detail says: not configured, unreachable, busy, timeout, error).
- Real runs (Qwen2.5-0.5B Q4, synthetic drafts, not user data): scripts/verification/esai_essay_critique_run2_real_qwen0.5b.txt. Run 1 (kept raw) was contaminated: draft A contained the few-shot example's phrase, and the model echoed it. Run 2: 2 + 1 model spans kept, 2 model lines rejected (not exact / duplicate), types often generic.
- Not covered: no student UI, no semantic quality evaluation, no claim about the user's hardware. The existing heuristic tools (hook, conclusion, clarity) are unchanged. Loopback is not a privacy sandbox: the local model server can log the draft.
