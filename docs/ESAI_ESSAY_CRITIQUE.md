# Student-authored essay critique (scoped, unaudited)
POST /api/v1/study-abroad/essay-tools/critique {draft} (uses the same require_tenant dependency as the other m23 routes; auth was exercised only in the development mode, production OIDC behavior is not shown by these tests).
- Coaching only. The response never contains rewritten text: generated_essay_prose and revised_draft are null; every item has an EXACT quote of the student's draft; question text comes from fixed templates or our own measure wording.
- verified_measure items (always on, deterministic, no model, whole draft): sentences over 40 words (word count shown); a WHOLE word used 4+ times across the draft (count shown; the first sentence containing it is quoted, so the quote is one occurrence, not all).
- keyword_heuristic item (NOT verified): trait_word flags a sentence containing a trait phrase ("passionate", "hard worker", ...). It can flag sentences that already contain a concrete example and says so; it makes no claim about absence of examples.
- model_selected_span items: a local model (loopback only, no redirects, no env proxy, 12s budget, 2 slots) picks up to 2 phrases + a type (scene/evidence/reason/change); phrases (4-14 words) must be exact RAW substrings of the draft at word boundaries (no whitespace normalization, no mid-word cuts) or are rejected; the question is our template. Span choice and type fit are NOT verified (e.g. the "evidence ... shows this" template is a poor fit for a plain event).
- mode labels: model_selected_spans_plus_verified_measures / verified_measures_only_model_spans_rejected / verified_measures_only_no_model (detail says: not configured, unreachable, busy, timeout, error).
- Real runs (Qwen2.5-0.5B Q4, synthetic drafts, not user data): scripts/verification/esai_essay_critique_run2_real_qwen0.5b.txt. Run 1 (kept raw) was contaminated: draft A contained the few-shot example's phrase, and the model echoed it. Run 2: 2 + 1 model spans kept, 2 model lines rejected (not exact / duplicate), types often generic.
- Not covered: no student UI, no semantic quality evaluation, no claim about the user's hardware. The existing heuristic tools (hook, conclusion, clarity) are unchanged. Loopback is not a privacy sandbox: the local model server can log the draft.
- Draft size: the schema allows up to 20000 characters. Measures use the whole draft; the model sees only the first 6000 characters. The response reports processed.{draft_chars, measures_chars, model_chars_considered, model_truncated}.
- Load: 2 model slots; a timed-out call keeps its slot until its worker ends; further requests get a labeled "busy" measures-only response immediately (tested: 30 follow-up requests in under 2s, thread growth <= 6).
