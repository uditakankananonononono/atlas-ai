# Claire SQL decision journal

`POST /api/v1/claire/journal/decisions` stores an explicitly owner-reported decision, one-line reason, context and source reference under the authenticated tenant and actor. `GET /decisions?query=...` ranks matches with a stable hashed bag of words, not a semantic embedding or a trained model. `POST /corrections` stores original and owner correction as a distinct record. `DELETE /entries/{id}` removes one record; `DELETE /entries` erases the actor's journal. The source reference is recorded as reported and is not independently authenticated by this API. No stored decision gives permission for external action.

This is a durable alternative to the legacy process-local `atomic-concepts-1-23` decision journal, which remains for compatibility but should not be used for cross-process decisions. Both stores remain separate. No old in-memory data is migrated, since process-local entries have no trustworthy source binding or export. A new Alembic revision (`20260927_m21_owner_journal`) covers these tables, and was applied and smoke-tested against an empty local SQLite database; production upgrade has not been executed or verified. `create_all` covers local development only. Two new tests cover SQL persistence, tenant/actor isolation, invalid reasons, HTTP routes and deletion on Python 3.12. It is not the full Meemee merge, a model of the owner's intelligence, or an autonomous social scanner.
