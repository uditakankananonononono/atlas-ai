# c30.policy - Shared standing-rules guard (v2 gate layer)

## Source pin
Spec v2 section 0 standing rules (verbatim): "no spend without per-action approval (POLICY_REFUSED_SPEND); no email/DM/outreach/application submission without her exact-draft approval (POLICY_REFUSED_OUTREACH); no fake accounts, bots or multi-account posting (POLICY_REFUSED_FAKEACCT); no autonomous posting (POLICY_REFUSED_AUTOPOST); no scraping that breaks a site's terms or auth walls (POLICY_REFUSED_SCRAPE); no real-money trading (POLICY_REFUSED_TRADE); free tiers first. Every unit imports the guard; mutation battery must prove removing it fails a test."

## What it does
Owns the six standing refusals as one map; `check(action, prefix)` raises `<prefix>_REFUSED_<RULE>` so the refusal carries the calling unit's family prefix. `clean_text` centralizes text hygiene (type/blank/Cc-Zl-Zp control characters/length). `scope` builds the mandatory honesty block (`implemented`, `not_implemented`, `data_source`, `as_of`).

## What it does not do
It does not authorize anything: an m00 allow for a gated class is not approval to bypass this layer, and hard-refuse classes cannot be overridden at all. It makes no network, account or filesystem use. Unknown actions never pass: they refuse (fail-closed).

## Limits
- Six rules, closed set. Text fields: caller-supplied limits per call site.
- IC: refusal strings carry the unit prefix (spec shows `POLICY_REFUSED_*` at guard level; units' own prefixes are the per-unit `<PREFIX>_REFUSED_*` rule from spec section 0).

## Repair addendum (S2 audit, canonical surface rulings)
- check() is fail-closed: an action outside RULES refuses `<prefix>_REFUSED_UNKNOWN:<action>`; nothing passes with docs.
- Refusal prefixes are per-unit: each family calls check() with its own prefix (TREND/SOCIAL/FLEET/APPLY/...), e.g. S2.11's fake-account refusal is SOCIAL_REFUSED_FAKEACCT. Verified: every check() call site uses its module's own PREFIX.
- check_account(platform, existing, prefix) enforces one-account-per-platform in any account-creation path: any existing account on the platform (official or fake) refuses <prefix>_REFUSED_FAKEACCT; otherwise it returns the single official-account descriptor for the caller to propose.

## Canonical descriptor adapter (auditor-4 canonical surface)
- Descriptor: exactly {class, module_id, tenant_id, action_type, payload}; anything else POLICY_REFUSED_BAD_DESCRIPTOR:<field>; unknown class POLICY_REFUSED_UNKNOWN:<class>. Payload must be finite JSON.
- classify(descriptor) is side-effect-free: offline class allows only action_type in {analyze, draft, plan, record, read}; hard classes (fakeacct, autopost, trade, scrape) always refuse and NO m00 allow can override; spend/outreach return needs_approval and are NEVER allowed from supplied booleans or token-looking data. Checking creates no m00 state.
- bind_spend binds merchant/resource/item/options, final amount+currency+quantity+fees, undo terms and one effect_id; changed cost or item = new descriptor = new review. bind_outreach binds sender, channel, send_at, all to/cc/bcc, exact subject/body, attachment hashes and body_sha256 = SHA256 of the exact UTF-8 body.
- execute(descriptor, approval_id, ...) treats approval_id as a lookup reference, not bearer authorization; it re-validates the descriptor, refuses hard classes outright, and delegates to m00 consume_effect_checked with the unchanged descriptor (tenant/module/action/payload binding, status/expiry/consumed/drift rejection live in m00). The consume callable is injected; no persistence is duplicated here.
- Class/action compatibility is enforced in validate_descriptor: spend class requires action_type "spend", outreach requires "outreach"; relabeling a hard class as gated (or vice versa) refuses POLICY_REFUSED_BAD_DESCRIPTOR:action_type - the bypass is impossible by construction. Directly constructed descriptors face the exact same payload schemas as bind_* output (spend: required fields + typed amount/currency/quantity/fees; outreach: exact key set, typed fields, body_sha256 verified against the exact body bytes).
- Payload key integrity matches m00 _validate_payload_keys: every dict key anywhere in the payload tree must be a string (no JSON key coercion), so payload_hash cannot collide across coerced shapes. descriptor_hash matches m00 _request_hash byte-for-byte.
- Message-text policy: outreach BODY allows the ordinary message bytes LF/CR/TAB (allow_ws) and preserves approved bytes exactly (no normalization); SUBJECTS are single-line by policy - LF/CR/TAB refuse POLICY_REFUSED_CONTROL_CHAR:subject - and an empty subject is valid, a blank body is not. Every other Cc/Zl/Zp character still refuses.
- Registered-source rule: module_id must exist in app.modules.catalog.BY_ID (ids 0-25); unknown ids refuse POLICY_REFUSED_BAD_DESCRIPTOR:module_id. The adapter never classifies for an unregistered module.
- execute(descriptor, approval_id, *, actor, consume=None, effect_id=None, service=None, registry=None): with no injected consume it lazily resolves m00 default_service (or the given service) and calls consume_effect_checked, forwarding registry for state-drift probes.
- m00 expiry semantics (auditor-4 canonical ruling, m00 round-4 child): expiry gates the decision window of pending rows AND the atomic consumption of approved grants - an approved grant past expires_at refuses POLICY-level at consume_effect inside the consume transaction (race-safe); a permit consumed before expiry keeps its idempotent receipt after expiry.
- Legacy check(action, prefix) remains the deny-only compatibility wrapper with per-unit refusal mapping.
