# S4.5 / c35.prefill - Application prefill-and-tracker

## Source pin
Verbatim excerpt: "Apply super strategically to all opportunities on the internet".
Provenance: pinned as delegated, not independently recovered from a user
channel; the pin, message id and offsets cited in the delegation's spec file
are unverified external content on this side.

## What it does
Builds prefill packets from a SUPPLIED profile, a deadline calendar and an
effort/EV ranking over SUPPLIED opportunities. "All opportunities on the
internet" is substituted by the supplied set. Per opportunity: requested
fields fill from the profile on exact key match, unmatched keys list as
missing_fields, essay-type fields stay draft_required. Tracker rows carry
status in {not_started, prefilled, needs_input, expired} derived from the
supplied data. Ranking is computed: score = (value * p_win) / effort_hours
with caller-supplied numbers only; sorted score desc, deadline asc, id asc;
rows missing any of the three numbers are unranked with a reason flag.
Calendar sorts by deadline with days_left vs the supplied as_of.

## What it does not do
Never submits (X6): any submit/password/login token in ANY key -
top-level request keys, profile keys, opportunity keys, or requested
field names - refuses APPLY_REFUSED_SUBMIT before processing (substring,
case-insensitive). No send/submission path exists (verified, keep true). It does not know true win
probability; the ranking is only as good as the supplied numbers and says
so in scope.not_implemented. No startup-grant matcher (separate later
unit). No network, no scraping, no outreach, no account creation, no spend.

## Refusals
APPLY_REFUSED_NOPROFILE (missing/empty/non-dict profile),
APPLY_REFUSED_SUBMIT (submit/password/login key or field),
APPLY_REFUSED_BAD_TYPE:{request, opportunity, fields, value, p_win,
effort_hours, deadline, as_of, profile_value} (wrong types; effort_hours <= 0;
malformed dates),
APPLY_REFUSED_EMPTY:opportunities (empty supplied set),
APPLY_REFUSED_OVERSIZE:{profile, opportunities, fields} (caps exceeded),
APPLY_REFUSED_NONFINITE:score (computed score overflows to non-finite),
plus policy.clean_text refusals (EMPTY / CONTROL_CHARS / TEXT_TOO_LONG)
on text fields.

## REPAIR addendum (auditor-4, fixed)
Numeric hygiene: value/p_win/effort_hours must be finite numbers (NaN and
Infinity refuse); p_win must be in [0, 1]; effort_hours > 0; profile
numeric values must be finite (bool refuses); a computed score that
overflows to non-finite refuses APPLY_REFUSED_NONFINITE:score rather than
emitting an unorderable, non-JSON-safe number.
Dates: canonical YYYY-MM-DD only (verified by shape before parsing) -
fromisoformat alone accepts basic (20261101) and ISO-week forms whose
strings would sort lexicographically, not by actual time. Mixed forms
refuse APPLY_REFUSED_BAD_TYPE:{deadline, as_of}.

## Policy guard
Uses backend/app/modules/c30/policy.py: clean_text for every caller text
field, policy.scope for the honesty block. Pure-offline unit: no action
path exists, so none of the six standing rules (spend, outreach, fakeacct,
autopost, scrape, trade) has a code path here; the test suite proves the
module exposes no function that spends, sends, posts, trades or creates
accounts and that policy.check refuses all six.

## Limits
<= 512 opportunities, <= 64 requested fields per opportunity, <= 128
profile keys; text fields length-limited by clean_text. Deterministic:
same input gives byte-identical output (json sort_keys); scores rounded to
6 places; the only clock is the supplied as_of. Interpretation choices:
essay-type detection is exact normalized-name match against a closed set
(essay, personal_statement, statement, statement_of_purpose, cover_letter,
motivation, motivation_letter, sop); blocked-token matching is
case-insensitive substring over opportunity keys and requested fields
(refuse-closed); expired rows still rank (expiry is tracker status, not a
ranking exclusion); missing "fields" defaults to an empty list.
