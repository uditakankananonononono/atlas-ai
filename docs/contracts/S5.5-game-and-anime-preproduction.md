## Input and validation

run(request) -> plain dict. Exact built-in request dict; keys as_of/mode/concept.
concept dict keys title/premise/characters/episodes/mechanics; character dict keys
name/trait. Unknown keys refuse UNKNOWN:request/concept/characters, never echo keys.
Exact str/list/int types at caller boundaries, no subclasses; episodes bool refuses.
Known characters/mechanics list counts <=30 are checked before bounded key scan.
Raw title200/premise2000/name200/trait200/mechanic64/mode200/as_of10 caps precede
membership and clean_text; keys raw200. Over-cap -> OVERSIZE:<field>, never shared
TEXT_TOO_LONG. Each dict has at most32 keys and each list/tuple at most64 items, checked
before materialization/traversal (OVERSIZE:request). Known lists retain30 cap.
Container traversal maximum10000 occurrences/depth32 (root0,
scalar depth counted), cycles BAD_TYPE:request; resource overflow OVERSIZE:request.
Cc/Cf/Zl/Zp raw keys/text refuse CONTROL_CHARS:<field>; Zs remains unchanged.
Real landed policy.clean_text and scope only, no fallback or policy.check action.

Forbidden keys normalized casefold/hyphen-to-underscore, exact table membership,
precedence SEND>SPEND>PUBLISH>NOCREDS and alphabetical matched key within class:
SEND send/approve/approved/approval/approval_token/smtp/token/email_send/sender/
smtp_host/smtp_port/smtp_user; SPEND pay/purchase/spend/buy/checkout/card_number;
PUBLISH publish/upload/monetize/revenue/roblox_api/deploy; NOCREDS login/password/
username/credentials/otp/api_key/access_token/refresh_token/bearer/pass/passwd.
Reason VENT_REFUSED_<class>:<matched-table-key>. Non-str keys BAD_TYPE:key after
scan; values are never treated as execution instructions. Unknowns refuse safely.

as_of ASCII fullmatch YYYY-MM-DD plus calendar date; BAD_TYPE:as_of on short
malformed dates, OVERSIZE:as_of over10. Mode exact game/anime; ordinary unknown
string UNKNOWN:mode, non-str BAD_TYPE:mode, over200 OVERSIZE:mode.

Title/premise required nonblank. characters/mechanics optional in unused mode,
but supplied fields still fully validated. Game requires nonempty mechanics;
anime requires nonempty characters and exact int episodes1..24. EMPTY:mechanics/
characters for required empty lists, BAD_TYPE:<field> for malformed values/episodes.
Missing/None episodes ignored only for game. Characters require nonblank name/trait.

Mechanics require ASCII identifier fullmatch [A-Za-z_][A-Za-z0-9_]*, unique exact
names; duplicate/invalid -> BAD_TYPE:mechanics. Sanitizer also rejects Lua reserved
words and any case-insensitive substring http/require/loadstring/socket. This
restriction exceeds identifier grammar deliberately: valid identifiers can collide
with Lua keywords or violate the specified no-network-token output gate.

## Frozen output

Exactly {documents, scope}. Game documents has game_design.md and mechanics.lua.
Design Markdown: supplied title/premise, Mechanics bullet list; Core loop, Win/Lose,
UI list show TO_WRITE (no unsupported prose). Lua file: one comment and
`local function <mechanic>() end` per supplied mechanic. Empty function is explicitly
unimplemented, not a working game or network-capable scaffold.

Anime documents has series_bible.md and episode_beats.md. Bible uses supplied title,
premise, names and traits only. Episodes numbered1..N each with Act1/2/3 TO_WRITE.
No shot_lists/storyboards/panel_plan/scenes/scripts keys; no scene format or panel/
shot planning. Supplied prose is not censored for those words; exclusion concerns
computed structure, not arbitrary source strings.

scope is the real policy block: implemented rendered supplied-game document/Lua
stubs and anime bible/fixed acts; not_implemented publishing/monetization/execution/
creative-quality claim/shot-panel-storyboard-scene formatting; data_source supplied
request only, as_of caller date. No file writes, network, publishing, sending,
account creation, payment or API/tool invocation. Pure offline applicability means
none of the standing effect rules has a dispatch path; no input can add one.
