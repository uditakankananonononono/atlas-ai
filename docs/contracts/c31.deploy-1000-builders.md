# c31.deploy-1000-builders (S1.7 fleet scheduler, synthetic proof)

## Source pin (v2 spec, S1.7 "Fleet scaling")

> "scheduler/queue that can enqueue and track 1,000 builder jobs with isolation, per-job
> budgets and a global concurrency cap set by the actual hardware or approved compute.
> Proven with a 1,000-job synthetic run (stubs) to test the scheduler; real concurrent
> LLM builders are limited by API limits and spend (approval). Report actual concurrent
> count." (X19: 1,000 queue capacity proven synthetically)

## Scope

- implemented: synthetic 1,000-job queue proof over the troop roster machinery
  (`backend/app/troop/roles.py`: TemplatePlanner -> ActionWorker -> RuleReviewer) with
  wave scheduling under a configured concurrency cap, per-job budgets, a global budget
  ledger and a per-agent audit log. Module: `backend/app/troop/s1_7_scheduler.py`
  (additive; `runner.py` untouched).
- not_implemented:
  - real concurrent LLM builders - limited by API limits and spend (approval)
  - no live accounts, outreach, purchases or spend (`FLEET_REFUSED_SPEND`)
  - hardware/compute-derived caps - the cap is caller-declared (1..256), not probed
- data_source: supplied+synthetic
- hermetic: stdlib only; no network, no clock, no RNG.

## Payload

Exactly one of `jobs` (explicit list) or `synthetic_jobs` (count 0..1000). Required:
`as_of`, `concurrency_cap` (1..256), `per_job_budget` (0..1e6), `global_budget`
(0..1e12). Explicit job fields: `id` (unique, safe text), `kind` (`sum_table` |
`text_stats`), optional `rows`/`text`/`top_n`, optional `cost` (0..1000, default 1).
Synthetic job `i` is `{"id": "syn-%04d", "kind": "sum_table", "rows": [{"a": i, "b": 2}]}`
(deterministic).

## Scheduling

Jobs are canonically sorted by id, sliced into waves of `concurrency_cap`. Wave `w`,
slot `s` runs on agent `builder-%03d(s)`; slots are reused across waves. Each job runs
plan -> per-step worker/reviewer with at most 2 attempts. Jobs whose `cost` exceeds
`per_job_budget` are marked `over_budget`, never executed, never debited. If the sum of
runnable costs exceeds `global_budget`, the whole run is refused before execution.
Concurrency is reported as numbers: `concurrency_cap` (configured) and
`measured_max_concurrent` (instrumented on the synthetic thread pool, run-dependent,
bounded by the cap). Never an "all" claim.

## Refusals (stable strings)

- `FLEET_REFUSED_OVERCAP:queue_capacity_is_1000` (jobs or synthetic_jobs > 1000)
- `FLEET_REFUSED_SPEND:synthetic_stubs_only_no_live_accounts_outreach_or_spend`
  (any truthy of purchase/spend/real_llm/live_api/outreach/live_accounts)
- `FLEET_REFUSED_BUDGET:global_budget_exceeded`
- `FLEET_REFUSED_JOB_SOURCE:choose_exactly_one_of_jobs_or_synthetic_jobs`
- `FLEET_REFUSED_BAD_TYPE:<name>`, `FLEET_REFUSED_UNKNOWN_FIELDS:<where>`,
  `FLEET_REFUSED_EMPTY_FIELD:<name>`, `FLEET_REFUSED_TEXT_TOO_LONG:as_of`,
  `FLEET_REFUSED_UNSAFE_CHARS:<name>` (category Cc, U+00A0, U+2028, U+2029),
  `FLEET_REFUSED_OUT_OF_RANGE:<name>`, `FLEET_REFUSED_DUPLICATE:<job_id>`,
  `FLEET_REFUSED_BAD_KIND:<kind>`

## Interpretation choices (invented shapes, not in the spec text)

- `FLEET_REFUSED_BUDGET` and `FLEET_REFUSED_JOB_SOURCE` codes are invented (spec names
  only `FLEET_REFUSED_{OVERCAP,SPEND}`); both follow the same prefix convention.
- Per-job budget semantics: over-budget jobs are skipped with status `over_budget`
  rather than aborting the run; the global budget gates the whole run up front.
- `measured_max_concurrent` is instrumented and run-dependent; deterministic artifacts
  are the schedule, ledger, audit log and outputs.
- Concurrency cap range 1..256 is an invented bound (spec defers to hardware).
