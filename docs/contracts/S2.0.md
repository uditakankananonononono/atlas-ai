# S2.0 / c32.ingest - Continuous-ingest pipeline

## Source pin
Verbatim excerpt: "Continuously do this and never stop, make sure that it is able to handle that much of data".

## What it does
Sharded, resumable, deduplicating ingest over SUPPLIED record batches with a throughput/coverage ledger (ingested/duplicates/shards computed). Checkpointed resume. `benchmark()` folds peer units U02 (capacity) and U38 (throughput): synthetic generated records, measured records/second.

## What it does not do
Never fetches, crawls or scrapes (`TREND_REFUSED_SCRAPE` via c30.policy). "Never stop" is bounded to resumable checkpointed batches, not unattended operation. No real-source ingest in benchmark (synthetic only). Checkpointing is real: on resume the unit skips `checkpoint.shard * shard_size + checkpoint.offset` already-applied records without re-validating them or touching the dedupe set, and every call returns `skipped` and the `next_checkpoint` {shard, offset} for the consumed prefix; a checkpoint past the end of the supplied batch refuses TREND_REFUSED_CHECKPOINT_RANGE.

## Refusals
TREND_REFUSED_SCRAPE, TREND_REFUSED_OVERSIZE (shard_size > MAX_SHARD; benchmark records_count > MAX_BENCH), TREND_REFUSED_NOCHECKPOINT (resume without checkpoint), TREND_REFUSED_CHECKPOINT_RANGE (checkpoint past batch end), TREND_REFUSED_BAD_TYPE:* (including benchmark shard_size <= 0), TREND_REFUSED_EMPTY:id, TREND_REFUSED_CONTROL_CHARS:id, TREND_REFUSED_TEXT_TOO_LONG:id.

## Limits
MAX_SHARD = 100000; MAX_BENCH = 2000000 (benchmark record count); id <= 256 chars. IC: refusal strings, ledger keys, checkpoint shape {shard, offset}, shard arithmetic and the benchmark's synthetic generator are interpretation choices. The spec's "10M-record fixture" is parameterized: benchmark(n) proves the mechanism; test runs n=200000.
