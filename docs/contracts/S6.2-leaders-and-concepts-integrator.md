# S6.2 leaders and concepts integrator

cross-account builder package, provenance held privately

## What it does
Turns SUPPLIED source passages into structured entity records (person,
company, product, concept) with evidence spans, plus fixed-template idea
prompts per confirmed entity. Pure function, stdlib only, offline,
deterministic. Guard: `from app.modules.c30 import policy`.

## Interface
`run(request: dict) -> {"entities", "prompts", "coverage", "scope"}`

request keys: `as_of` (str, required), `passages` (non-empty list of
`{id, url, text}`, required), `known_entities` (list of `{name, type}`,
optional, type in {person, company, product, concept}), `focus`
(str <= 200 chars, optional; gates template T1).

Entity record: `{name, type, status(confirmed|candidate_unconfirmed),
mentions[{passage_id, offset, snippet}], first_seen(=as_of),
homonym_types?}`. `homonym_types` is present only when the same name is
known under more than one type; each homonym is a separate record.

Prompt record: exactly `{entity, template_id(T1|T2), text,
label:"template_prompt"}`. Render-only binding of the two fixed templates:
- T1 `What would {name}'s approach look like applied to {focus}?` - emitted
  per confirmed entity only when `focus` is supplied.
- T2 `How does {name} compare with {other}?` - emitted per confirmed entity
  only when >= 2 confirmed entities exist; {other} is the next entity in
  name-sorted order, wrapping.
Candidate entities get NO prompts.

## Finding entities
- Known entities: case-sensitive exact match of every occurrence.
- Candidates: ASCII regex `\b[A-Z][a-z]+(?: [A-Z][a-z]+){1,3}\b` (2-4
  tokens; no acronyms, no single tokens, no non-ASCII).
- Overlap at one passage: longest span wins; a known entity beats a
  candidate on the same span; a candidate equal to a known name is not
  duplicated. Mentions dedupe by (passage_id, offset).
- Offsets are 0-based code points into the raw supplied text. clean_text
  validates text only; offsets are never taken from cleaned text.
- Snippet = `text[max(0, off-60):off+len+60]` clipped to 160 chars.

## Passage gate
A passage is used only if its url starts with `https://`, has a non-empty
hostname (urlsplit), and contains no whitespace or control characters, and
its text is a non-blank string. No live URL check. Drops are counted in
`coverage.dropped_by_reason` as `no_https_url` / `empty_text`.

## Refusals (ValueError, codes INTEL_REFUSED_*)
- BAD_TYPE:request - request not a dict
- BAD_TYPE:passages - passages missing/not a list, or a row not a
  {id, url, text} dict with non-blank string id
- EMPTY - passages is an empty list
- NOSOURCE - every passage dropped by the gate
- BAD_TYPE:known_entities - blank/non-str name, or type outside the closed
  set
- BAD_TYPE:as_of / TEXT_TOO_LONG:as_of - via policy.clean_text
- BAD_TYPE:focus / TEXT_TOO_LONG:focus - via policy.clean_text (max 200)
- UNSOURCED - internal invariant: a record with zero mentions can never be
  emitted (reachable only by direct internal call)

`known_entities` missing -> treated as []. Zero entities found is SUCCESS
with `entities: []`, not a refusal.

## Coverage
`{passages_supplied, passages_used, dropped_by_reason{no_https_url,
empty_text}, entities_found, known_not_found[]}` (known_not_found sorted).

## Determinism
Sorted keys throughout; byte-identical JSON across runs of the same input;
no wall clock except the `as_of` input. Local review: Python 3.10.12 only; peer baseline 3.12.14 is peer-stated, not reproduced here.

## Composition note
c37/__init__.py is composition-owned. This unit never writes it; tests load leaders.py by file path.

## Honest limits
Regex candidates are capitalized-phrase heuristics, not verified entities;
they are flagged candidate_unconfirmed. No knowledge graph, no entity
resolution beyond exact name match, no judgement of who is a "leader", no
live fetch, no verified entity facts. Non-ASCII names are found only via
the known_entities list, never by the candidate regex.

## Review rulings and disclosures
Duplicate passage IDs refuse INTEL_REFUSED_BAD_TYPE:passages without ID echo.
Duplicate exact (name,type) known entries refuse INTEL_REFUSED_BAD_TYPE:known_entities;
same name/different type remains a legal homonym. Names validate with the real
policy.clean_text(name, INTEL, name, MAX_NAME), cap 256 and unchanged helper
control/type/empty/too-long refusals. Whole-list per-field validation precedes
duplicate checks and matching. Absent or explicit None known list defaults empty. Every other non-list value,
including {}, 0, empty string and False, refuses BAD_TYPE:known_entities. No T2 homonym self-comparison skip change in this child.

Known-entity list and match count are unbounded. A peer-reported pathological
1-character name versus 100,000-character text took over 25 seconds; local
review does not claim to have reproduced that duration. No runtime timeout or
matching complexity fix is included. Candidate extraction is ASCII-regex-only;
Unicode known names can still match exactly. Raw supplied text is not fact
verification. These outputs cannot authorize actions.

Pure-offline applicability: spending, outreach, account creation, autoposting,
trading and scraping have no execution path in this module. Tests check no
public effect function is exposed; policy helper is real, never replaced.
Independent peer acceptance and external validation remain separate.

Passage row IDs are validated for clean text and the 256-character cap before
the URL-drop gate, even for dropped rows. Duplicate-ID checks count dropped
rows too; invalid or overlong dropped-row IDs refuse rather than being skipped.

## Remaining audit disposition
Agreed-equivalent surviving operators, for the public validated pipeline:
L40-42 URL gate None/False and redundant space bound; L83 five sort/tie
operators (mixed confirmed/candidate equal-name tie is unreachable); L91
break-to-pass leaves overlap true; L148-149 duplicate pid/start path is
unreachable with unique IDs and exact known keys; L161 entity sort duplicates
the already-sorted grouped traversal; L136 clean_text field-label change is
harmless because the same ID was validated first. These are scoped audit
arguments, not a zero-survivor guarantee for arbitrary internal callers.
Candidate-to-known adjacent spans are retained and now explicitly tested.

Residuals, not repaired: T2 may compare homonym records with the same name;
known-entities by text matching is unbounded (over-25-second duration is
peer-reported, not locally mounted); ASCII-only candidate regex; integration
route, full suite and Docker PostgreSQL remain unverified.

## URL character rule revision
URLs refuse ASCII 0..32, DEL127, C1 128..159, NBSP, Unicode line/paragraph
separators, U+200B..U+200F, U+202A..U+202E, U+2066..U+2069 and U+FEFF.
Within 0..159 only 33..126 are accepted by the character gate (other URL
requirements still apply). Other fields are unchanged. Historical audit
equivalence discussion about old URL bounds is superseded by this rule.
