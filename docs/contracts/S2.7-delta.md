# S2.7 delta: supplied dossier timeline and evidence

Status: IMPLEMENTED-BOUNDED. Extends, never replaces,
`c32.dossier.dossier`; original implementation and tests remain unchanged.

## Design rationale

The delta interprets broad dossier research as bounded extraction from supplied
sources, with strict subject mentions, a timeline and evidence-depth counts.
These mechanisms are design choices, not claims of exhaustive research or
permission to fetch sources or take external actions.

## Interface

`app.modules.c32.dossier_timeline.dossier_v2(request)` and `run(request)` return a
plain JSON-compatible dict. No HTTP mounting, filesystem writes, fetches, account
sessions or persistent report store. Inputs: subject, sources, optional aliases,
known_entities, include_private, as_of. Unknown request/source fields refuse.

Sources may be passed as a list or a tuple (both accepted by ruling; any other type
refuses TREND_REFUSED_BAD_TYPE:sources). Each source is a supplied url/text record with optional published string. Published
is validated as text but is not used to assign event dates. Public-source status
and source truth are caller declarations, not verified. as_of is caller-supplied
text (default supplied-input), not independently confirmed recency.

## Extraction rules

- Full normalized subject or explicit alias matches only: casefold, punctuation
  to spaces, collapse whitespace, exact normalized phrase boundaries. No implicit
  first-name match. Subject-token-only sentences become ambiguous_mentions and do
  not contribute facts/timeline. Single-letter initials survive sentence splitting.
- Each matched sentence normalized with the same case/space/punctuation rules is
  one fact. Separate source URL strings accumulate once each; repeated copies of
  the same URL do not increase corroboration. URLs are not fetched/canonicalized
  or checked for publisher independence.
- Five legacy dimensions/keywords retained; select top eight unique facts per
  dimension after dedupe, descending distinct URL count then first source/sentence
  order. A fact can belong to multiple dimensions. citation_count counts retained
  bucket entries, not unique external evidence. truncated_fact_count is discarded
  bucket entries. Evidence depth includes per-dimension count, corroboration counts
  and number of distinct supplied URL strings.
- Lexical year, English month/year (full or abbreviated month), ISO date extraction;
  dates validated against calendar rules and sorted ascending by date then fact ID.
  Precision is year/month/day. Invalid ISO dates are not reinterpreted as bare years.
  Every dated matched sentence can appear in the timeline, including matched
  sentences outside dimension keywords. Undated sentences are separate. No dates
  inferred from publication metadata. Timeline and undated outputs are deduped facts.
- Different extracted years in sentences containing the same full trigger word
  (founded, born, joined, launched) surface an unresolved potential conflict with
  citations. This is a broad lexical screen, not semantic truth: the years may
  describe separate ventures/events or unrelated dates in the same sentence. It
  never picks a winner, silently drops conflicting candidates, or claims resolution.
- Supplied known entity names use phrase-boundary matching on matched fact text;
  output links carry fact IDs and supplied source URLs. No external lookup.

Completeness remains five-slot coverage/5, rounded to six decimals, not internet
coverage. Full-source count is computed. Reports list every-single-thing coverage
as not implemented and never repeat the aspiration as a achieved claim.

## Caps and refusal table

128 sources, 200000 text characters per source, 512 per URL, 128 subject/alias/entity,
16 aliases, 128 known entities, 64 published string, 128 as_of. Eight facts per
legacy dimension, after dedupe. Other outputs scale with this bounded supplied input;
no continuous-stream/aggregate corpus claim is made.

| Code | Condition |
| --- | --- |
| TREND_REFUSED_PRIVATE | include_private true |
| TREND_REFUSED_ALIAS | aliases wrong type, >16, blank/control/oversize alias |
| TREND_REFUSED_BAD_TYPE:<field> | invalid request, source/entity/list/field types or unknown keys |
| TREND_REFUSED_EMPTY:<field> | required text or sources empty |
| TREND_REFUSED_CONTROL_CHARS:<field> | shared policy Cc/Cf/Zl/Zp restriction |
| TREND_REFUSED_TEXT_TOO_LONG:<field> | shared text cap |
| TREND_REFUSED_OVERSIZE | >128 sources |

No NODATE refusal: undated matched sentences are returned separately. No
CONFLICT_UNRESOLVED refusal: conflicts are surfaced in successful reports.

## Policy and LIMITS

Imports the real landed `from app.modules.c30 import policy`; uses clean_text
and scope with no local substitute. Pure-offline applicability: spend, outreach,
fakeacct, autopost, trade and scrape have no callable or dispatch path. Unknown
fields cannot add an action. Tests pin the real policy identity/hygiene calls and
absence of send/post/spend/trade/create_account/fetch exports. policy.check denies
all actions; it is deliberately not invoked for pure offline analysis.

No live sources, private-data collection, public-status verification, independently
verified fact correctness, source independence, human thinking/semantic understanding,
exhaustive coverage, venture-specific completeness denominator or continuous ingestion.
Explicit aliases are supplied identity mappings, not verified identity evidence.
Default legacy text hygiene rejects LF/CR/TAB; multiline-source acceptance was not
part of this delta and needs a separate approved text-normalization decision.
Source URL strings are evidence labels, not verified URLs. Conflicts may overflag;
normalization may merge punctuation-dependent distinctions. No resolution claim.
No automatic stream integration: S2.0 id/text persistence does not preserve this
provenance schema. HTTP/auth/report integration and full regression remain separate work.
