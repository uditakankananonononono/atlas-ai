# c34.prototype (S3.1 trend-to-product prototyper)

Spec scope: from a trend brief, emits spec, mockup site (static HTML), CAD-free gadget spec/BOM, and a free-tool build plan. Paid software is replaced by an in-repo substitute generator. Refusals `PROTO_REFUSED_*` (SPEND, UNSAFE).

## Scope
- implemented: `run_prototype(payload)` in `backend/app/troop/s3_1_prototyper.py` (additive; no routes, no wiring). Pure, deterministic, standard library and real shared c30.policy only, no network, clock or RNG. Returns `{unit, spec, site_html, gadget{spec, bom, total_cents, currency}, build_plan{tools, steps}, scope}`.
- not_implemented: trend discovery (trend is supplied, not fetched or verified); any novelty or creativity judgement ("mimics human creativity" is not claimed); physical prototype, CAD, part ordering; any spend. LIMITS: this emits documents from the caller's brief; it does not show a product is good, new, safe, or buildable. BOM costs are the caller's numbers.
- data_source: supplied.

## Payload
`as_of` (text <=64), `brief`: `name` (<=80), `trend` (<=200), `audience` (<=120), `features` (1..8 texts <=120, unique), optional `components` (0..30 of `{name, qty 1..10000, unit_cost_cents 0..10000000}`, unique names), optional `tools` (0..10 of `{name, kind in site|bom|spec, paid bool}`, unique names), optional `currency` (3 capital letters, default USD). Text fields: no leading/trailing whitespace, no Cc, Zl, Zp or Cf characters; Cf is refused by real c30.policy.clean_text as CONTROL_CHARS. Spend flags `purchase, spend, order_parts, live_api, buy_paid_tools` are accepted at payload level only to be refused when truthy.

## Output
- site_html: static HTML, every interpolated field html-escaped, no scripts, links or external references; line count is 14 + number of features.
- spec: `# Product spec`, blank line, one line per spec entry.
- tools: each tool, paid or not, is mapped to an in-repo generator (`in-repo:site_html_generator`, `in-repo:bom_generator`, `in-repo:spec_generator`) at cost 0.
- steps: fixed four steps, the last is owner review before any build or purchase.

## Refusals (stable strings, never echo input; checked in this order)
shape/type (`BAD_TYPE:<path>`, `UNKNOWN_FIELDS:<where>`) -> `SPEND:no_purchase_paid_tool_or_live_api` -> as_of and brief fields in order (`EMPTY_FIELD`, `TEXT_TOO_LONG`, `UNSAFE_CHARS`, `CONTROL_CHARS`, `OUT_OF_RANGE`, `DUPLICATE`, `BAD_KIND`, `BAD_VALUE`) -> `UNSAFE:<path>` (first field in order name, trend, audience, features, components, tools). All prefixed `PROTO_REFUSED_`.

## Interpretation choices (IC)
- IC1: module location `backend/app/troop/`; test at `tests/troop/`; doc at `docs/contracts/c34.prototype.md`. Route `/c34/prototype` is not created.
- IC2: "trend brief" input shape is invented (fields above); spec gives no schema.
- IC3: UNSAFE is a denylist (weapon(s), firearm(s), explosive(s), bomb(s), poison(s), malware, ransomware, spyware, stalkerware), case-insensitive, matched as substrings with a trailing word boundary so compounds (firebomb, bioweapon) are refused and "Bombay" is not. A denylist is not a safety review; it only stops the obvious. UNSAFE is also an invented trigger (spec names the code only).
- IC4: paid tools are not refused; they are substituted at zero cost. SPEND refuses only an explicit purchase/spend/live-API flag.
- IC5: money is integer cents; tool kinds limited to site, bom, spec (CAD-free per spec).
- IC6: limits (8 features, 30 components, 10 tools, qty and cost caps) are invented.
- IC7: real c30.policy.clean_text validates text after local length/whitespace and legacy Cc/Zl/Zp checks. Legacy UNSAFE_CHARS errors remain; Cf gives PROTO_REFUSED_CONTROL_CHARS:<path>. Exact builtin dict/list/str/int/bool types are required where the schema names them, not subclasses.
- Denylist scope is lexical, not semantic: no translation, homoglyph folding, punctuation removal or general safety analysis. Format characters cannot split a denied word because Cf refuses before matching. Nonlisted harmful ideas are not detected.
- Spend flag truthiness is intentional. False, 0, empty list/dict/string and None do not request a side effect and are accepted. Truthy flags refuse. No purchase or external execution exists regardless of flag value; accepting a falsy flag grants no spending authority.
