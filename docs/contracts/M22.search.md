# M22 search delta: fyyd, Software Heritage, source health

Status: builder-stated, reviewed by tests listed below. New files only; wiring is a separate unapplied patch.

## What exists already
`sources.py` covers blogs (dev.to, WordPress.com, Medium tags), articles (Hacker News), podcasts (iTunes shows and episodes, optional Podcast Index), and git hosts (GitLab, Codeberg), plus `collectors.py` (GitHub, PyPI, npm). This delta does not touch them.

## Added
| source | kind | endpoint | auth |
|---|---|---|---|
| fyyd | podcast | `https://api.fyyd.de/0.2/search/podcast?title=<q>&count=20` | none |
| softwareheritage | repository | `https://archive.softwareheritage.org/api/1/origin/search/<q>/?limit=20&with_visit=true` | none |

* Software Heritage: one request per search, never pages. Honours `X-Ratelimit-Remaining` / `X-Ratelimit-Reset` (refuses locally until reset when the window is spent) and HTTP 429 with `Retry-After`. Only origins with at least one visit are returned. Origins on github.com, gitlab.com and codeberg.org are named `owner/repo` so the service's name + URL dedup collapses them with the existing collectors. No person-level fields are emitted. The API terms allow free pointwise use and forbid bulk extraction.
* fyyd: public search needs no OAuth. `status != 1` raises `SourceError`.

## Health report
`source_health.health_report(collectors, query)` runs one query per source, concurrently, and returns status (`ok|empty|error`), count (cap 20), latency, newest dated item, and `stale` (True/False, or None when the source exposes no date). `python -m app.modules.m22_tools_hub.source_health "<query>"` prints it as JSON.

## fyyd terms citation (read 2026-10-11)
fyyd publishes no separate terms-of-service page that I could find: /terms answers 500, /agb, /tos and /nutzungsbedingungen answer 404, and the site's own pages are privacy policies (https://fyyd.de/datenschutz, https://fyyd.de/privacy-policy) and an FAQ (https://fyyd.de/fragen). The governing statement is the API documentation by the fyyd author, https://codeberg.org/eazy/fyyd-api (API base https://api.fyyd.de/0.2/). It says requests under /account need an access token for the identified user and "All other requests are free until now." Search is not under /account, so unauthenticated search is stated as free. It also says the API is a hobby project and "most likely to change", and it publishes no rate limit. This is a statement of current free access, not a licence for bulk use: the collector sends one request per search, no paging, no account endpoints, and no credentials. If fyyd adds terms or a limit, revisit.
