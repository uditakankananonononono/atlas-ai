# S2.1 supplied social-feed scanning core

Status: IMPLEMENTED-BOUNDED (local code capability). Not release clearance.

## Source pin

Assigned technical blueprint, AGI mega-spec v2 S2.1:
"analyse my feed across social media", "see my likes and comments on social media",
"see the people I follow and try to create similar work/products they have built but better".
These supplied excerpts are a design pin, not proof of authorization for live access or effects.
The parent corrected its original C1 label to S2.1. Spec C1 concept library is not built here.

## Interface

Host package: `app.modules.m20_general_cognitive_worker.c33_self_feed`.
`Scanner.run(tenant_id, connector, payload: bytes, as_of, action='analyze')`.
Two supplied-data connectors: `normalized_json` and `pasted_csv`.
A trusted integration can inject a `read(bytes) -> Iterable[dict]` connector and
`policy(action) -> bool` callable. An exact True from the callable AND action=analyze
are required before invoking a connector. No effect dispatch exists.

JSON envelope: exactly `schema_version: 1` (integer, not bool) and `records: list`.
CSV: exactly the following headers, no duplicates or unknown columns.
Each record has exactly seven strings: id, kind, platform, author, text, visibility,
source_ref. Kinds: liked_post, comment, followed_account, feed_post. Visibility:
public or owner; followed accounts must be public. Owner means the caller supplies
their own authorized export, not third-party private content. Identity fields cannot
be blank. Source refs accept supplied http/https URLs or export: references. URLs are
not fetched or authenticated. Duplicate platform/kind/id with unequal contents refuses.
Record byte/text caps and positive exact-integer config caps refuse oversize inputs.

Default limits: 2,000,000 input bytes, 5,000 records including duplicates, 10,000 text
characters per record, 2,000 per other field, 100 retained reports across tenants.
Limits can be lowered; max retained reports can be increased to 1,000. As-of must
be timezone aware; it labels the caller's supplied snapshot, not verified freshness.

Fixed word-level keyword counts assign one theme per record. Tie-breaks are alphabetical;
unmatched records are unclassified and generate no idea. Themes, unique counts and
source refs are computed from supplied data. Briefs are template-based unverified draft
hypotheses, never assertions of novelty, product quality or superiority. Input SHA256
and content-addressed report ID permit local reproducibility. Report results are detached
copies, tenant keyed, bounded and guarded by one in-process lock. No durability guarantee.

## Router integration

`routes.make_router(scanner)` exports authenticated POST `/api/v1/c33/self-feed/run`
and GET `/api/v1/c33/self-feed/report?report_id=...`. POST accepts connector, payload
(UTF-8 string) and as_of only. Tenant is obtained from require_tenant, never from the
body. Extra fields refuse. Validation responses use a fixed code and do not echo payloads.
Report lookup across tenant boundaries returns the same 404 as an absent report.

The router is NOT mounted in main.py or the global M20 router: additive-file isolation
was required. The integration owner must mount it once, bind the common policy, and
run combined regression. Core logic uses stdlib only; the optional route uses the repo's
FastAPI/Pydantic/auth dependencies.

## Refusals

SOCIAL_REFUSED_SCHEMA, NOEXPORT, CONNECTOR, THIRDPARTYPRIVATE, OVERSIZE, LIMIT,
CONFLICT, NOTFOUND; POLICY_REFUSED_ACTION. Prefixes expand on every actual code.
No requests to send, post, scrape, trade, spend or create accounts can be executed.

## LIMITS

- No live account/session access, network transport, auth-wall scrape, posting/outreach,
  schedule/continuous loop, platform-wide coverage, or external side effects.
- Normalized exports/pasted lists only. Instagram/LinkedIn raw vendor exports need
  separate verified versioned format adapters; they are not claimed supported.
- Python connector plugins are trusted dependency code, NOT a secure execution sandbox.
  Fixtures are offline mock inputs. Output revalidation cannot prevent a malicious plugin
  from making side effects. Do not load arbitrary user-supplied Python plugins.
- Privacy labels are supplied declarations, not independently proven ownership/license.
- No semantic model, endorsement, proven improvement, person profiling or human psychology.
- Shared c30.policy is absent from the public ancestor. Offline guard + injection interface
  is an explicit substitute, NOT satisfaction of the shared-import requirement.
- Store is volatile and capped globally; restart or eviction loses reports. No cross-worker
  persistence, continuous ingestion, or production resource/HTTP-size clearance.
- Full repo/bootstrap regression, mounted integration and third-party external validation
  have not run. Do not mark the broader S2.1 requirement done.

## Retained-report fairness note (independent-audit follow-up)

The default 100-report cap is shared across tenants. One tenant can evict another
tenant's retained reports. This affects availability, not cross-tenant read access.
The integrator must consider this at mount time; a per-tenant cap is a possible later
change. Re-running the same report refreshes write recency; GET does not refresh it.
