# S5.2 occupation/task proposal coverage map

Source: numbered Claire/Atlas program v2 S5.2, recovered from the spec-decomposition history. Source excerpt: "across all jobs in such a way that every business or work running on this earth is covered (something new or to help out massively and closing a gap)". This is PARTIAL against that aspiration.

## Mechanism and scope

`app.modules.c36.gaps.run(request)` computes a map and gaps from an explicitly supplied occupation/task taxonomy and explicitly linked automation proposals. No keyword matcher substitutes for verified automation. An occupation has proposal coverage when at least one task has a linked proposal. A task has proposal coverage when it has at least one link. Duplicate overlapping proposals cannot increase either numerator. Empty denominators return null. Taskless occupations remain visible in gaps. IDs match byte-exactly, output lists sort by IDs, inputs are not mutated, output records are detached.

Request: exact dictionary `{as_of, taxonomy_source, occupations, opportunities}`. `as_of` is an exact ISO calendar date. Occupation: `{id, title, tasks}`; task: `{id, text}`. Opportunity: `{id, occupation_id, task_ids, proposal, evidence_refs}`. All fields required. Occupation and opportunity IDs must be unique within their collection; task IDs unique within occupation. Each proposal has at least one task and one provenance reference. Unknown occupation or cross-occupation task references refuse. References are supplied unverified strings, never opened or treated as authority.

Output includes mapping, uncovered tasks, proposal records, measured supplied denominators and proposal-link percentages, `proposal_evidence=supplied_unverified`, `execution_coverage_verified=false`, and canonical policy scope. Proposals retain `status=proposed_unverified`. A 100% result means only every supplied task has an explicit supplied proposal. It is not world coverage or proven execution.

## Input boundaries

Exact built-in dictionaries/lists and strings only. Dictionaries cap32 keys, key128 chars; occupation count2000, task count200 per occupation, opportunity count10000, task references200, evidence references20. ID128, title/source/reference500, task text2000, proposal4000, date10. Collection caps checked before iteration, text caps before hygiene. Container subclasses are rejected without invoking their iterators. Nested objects in scalar fields are rejected without recursion. Total work is bounded by those caps. Shared input objects do not create aliases into output.

Every admitted dictionary rejects non-string/unsafe keys. Unknown keys refuse without echoing them. Recognized effect flags refuse regardless of truth value, before missing/unknown-field checks in that dictionary: spend/purchase, send/submit/outreach, fake_accounts, autopost, scrape, trade. They use the canonical deny-only `c30.policy.check`, not a local approval implementation. Casefold and hyphen normalization apply only to forbidden key recognition. No input approval or false flag creates permission. This list is the declared trigger surface, not universal semantic interpretation of prose. Arbitrary text remains data.

Refusal prefix `VENT_REFUSED_`, stable reasons: BAD_TYPE, OVERSIZE, UNKNOWN, MISSING, EMPTY, TEXT_TOO_LONG, CONTROL_CHARS with constant field suffix; BAD_DATE:as_of; DUPLICATE with constant identity/collection suffix; UNKNOWN_OCCUPATION; UNKNOWN_TASK; and the canonical policy refusals. No supplied ID, value, path or unknown key appears in errors.
