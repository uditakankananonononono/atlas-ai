## What the code does
Digests SUPPLIED release items per sector. Nothing is fetched, verified or inferred.
- Validation (drops are counted, never silent): https URL with host and no userinfo; `published` ISO date with age 0..`window_days` inclusive (default 14, integer 1..365) relative to the explicit `as_of` (later than `as_of` = dropped `future_date`; older than the window = dropped `stale`); sector exactly (case-sensitive) among the requested `sectors`, else dropped `sector_not_requested` (counted in `coverage.unattributed_dropped_by_reason`); well-formed metrics (finite numbers, boolean `higher_is_better`).
- Grades come ONLY from supplied labels, best claim wins. A = `peer_reviewed` with source journal or conference, or `benchmark` with a non-null `independent_reproduction_url`. B = `benchmark` + `third_party` + at least one metric with a baseline. C = `vendor_statement`; `benchmark` without reproduction that is vendor/unknown or third-party without baseline (raw values shown, no delta, no rank); `peer_reviewed` with any other source (also flagged `label_conflict`). D = `none`, unknown label, preprint, or no claims. Every grade prints as `supplied-label grade X (not verified by this unit)`.
- Score (A and B only) = mean direction-aware relative delta `(value-baseline)/|baseline|` (flipped when lower is better; zero baseline = not computable) x weight (A 1.0, B 0.6) x recency (linear 1.0 at `as_of` to 0.5 at the window edge). A `breakthroughs` item needs grade A or B, at least one computable delta, and score > 0; they are ranked per sector (score desc, id asc), top N (default 5, integer 1..100). A/B items with no computable delta or score <= 0 go under `notable`, unranked, flagged `no_positive_delta`. Eligible items cut by top N go under `notable`, unranked, flagged `cut_top_n`, counted in `coverage.cut_top_n` (global) and `coverage.<sector>.cut_top_n`. Unranked rows never carry `rank` or `score`. C goes under `notable` (deltas shown), D under `unverified`. A metric with `baseline_value == 0` is skipped in the average (flag `baseline_zero`, raw values shown, no epsilon).
- URL dedupe (global): normalize (lowercase scheme and host, drop fragment, trailing slash, `utm_*` params), keep highest grade, then newest `published`, then id asc. `coverage.duplicate_url_count` (global) and `items_dropped_by_reason.duplicate_url` (per the dropped item's sector).
- Output: `breakthroughs_by_sector[<sector>]` = `{breakthroughs, notable, unverified}`; `coverage` = `{by_sector[<sector>] = {items_supplied, items_used, items_dropped_by_reason, cut_top_n}, duplicate_url_count, cut_top_n, unattributed_dropped_by_reason, sectors_covered}`. Sector names are dict keys only under `by_sector` / `breakthroughs_by_sector`, never siblings of global keys, so a sector literally named `cut_top_n` is legal (tested); no reserved-name refusal. Also `integration_candidates` (open-source A/B breakthroughs, `ticket_stub_only_no_install`; open = exactly MIT, Apache-2.0, BSD, BSD-2-Clause, BSD-3-Clause, CC0, case-sensitive) and `scope` from `policy.scope`.
- Deterministic, stdlib only, no network, floats rounded to 6 places; `to_json` serializes with sorted keys.

## Refusal table (`ValueError("INTEL_REFUSED_<REASON>[:field]")`)
| Reason | When |
|---|---|
| BAD_TYPE:request / as_of / window_days / top_n / sectors / items | wrong type or range; bool and float refused; `sectors` missing, not a list, or containing a non-string or blank entry; `items` missing or not a list |
| EMPTY:sectors | `sectors` is an empty list |
| NOITEMS | `items` is `[]` |
| NOSOURCE | items non-empty but zero survive validation |
| CONTROL_CHARS:<field> | control characters (Cc/Zl/Zp) in a sector name or in request-level `as_of`, `window_days`, `top_n`: whole request refused (real `c30.policy` category set; TEXT_TOO_LONG:sector from `clean_text`) |

Item-level control characters never refuse the request: in a required item field (id, title, url, published, sector) the item is dropped as `malformed_control`; in an optional field (kind, license, metric name) only that field is dropped (kind/license become `unknown`, metric name null) and the item gets flag `malformed_control_dropped`. Item drop chain (spec 1c9ca428 item 21), first failure wins and each dropped item counts once: `sector_not_requested` (item sector missing, non-str, containing control characters, or not exactly one of the requested sectors), `id_invalid`, `title_invalid` (missing/null/non-str/blank/over 256 and 512 chars), `url_invalid` (missing/null/non-str/blank), `url_not_https` (present but not https, or no host, or userinfo), `published_invalid` (missing/null/non-str/blank/not ISO YYYY-MM-DD), `future_date`, `stale`, `malformed_control` (control character in id/title/url, last). Then dedupe on validated survivors only: `duplicate_url` counted in the loser's own sector. The exact allowed `items_dropped_by_reason` key set is those 10 keys; `bad_url`, `bad_date` and `bad_metric` are removed and a test pins the set. Drops with no requested sector to attribute go ONLY to `coverage.unattributed_dropped_by_reason` (`sector_not_requested`); `coverage.by_sector[s]` exists only for requested sectors and never carries that reason. Item 22 (spec e131ce45): the generic reason `malformed` is removed. A non-object entry in `items` counts as `sector_not_requested`, only in `coverage.unattributed_dropped_by_reason`. `claims` present but not a list is [] and the item is kept with item flag `claims_invalid` (once); a claim entry that is not an object is dropped alone with the same flag; neither is counted as an item drop. Item 23 (spec 3834ef67) for `kind`/`license`: `kind` must be exactly one of tool, paper, model, dataset (case-sensitive); missing or null is `unknown` with no flag; present but not a str, blank, over 64 chars or not in that set (the string `unknown` included, builder reading) is `unknown` with item flag `kind_invalid`. `license` has no enum: missing or null is `unknown` with no flag; not a str, blank or over 64 chars is `unknown` with item flag `license_invalid`; any other non-blank str up to 64 chars, `unknown` included, is kept as given and unflagged; `integrable_open_source` follows the exact set of item 8 only. A control character in either field keeps `unknown` plus `malformed_control_dropped` (item 12). Flags are set members, once each. Metric name is required (non-null, non-blank str): a control character drops that metric and flags the item `malformed_control_dropped`; a missing, null, non-str, blank or over-128-char name drops that metric and flags the item `metric_invalid`. If every metric of an item is dropped the item has no metric: it is never ranked (A/B go to `notable` with `no_positive_delta`). `coverage.metrics_dropped_by_reason` counts metric drops of kept items and ALWAYS carries all seven keys, zeros included: `malformed_control_dropped`, `metric_name_invalid`, `metric_value_invalid`, `metric_baseline_invalid`, `metric_direction_invalid`, `metric_not_object`, `metrics_not_list`. A metric with a non-finite or non-numeric `value`, a `higher_is_better` that is missing, null or not a bool (0 and 1 are not bools; no default direction), or a present `baseline_value` that is non-numeric, bool, NaN or inf is dropped the same way (flag `metric_invalid`, item kept, counted in `coverage.metrics_dropped_by_reason`); a null or missing baseline is legal. Name length up to 128 is accepted. There is no whole-item `bad_metric` drop. `metrics` missing or null is [] (no flag). `metrics` present but not a list is [] and the item is KEPT, flagged `metric_invalid`, counted once with reason `metrics_not_list`; it is notable and unranked. An entry that is not an object is dropped alone, the other entries are processed, the item is flagged `metric_invalid`, and each is counted with reason `metric_not_object`. Each drop is counted once, by first failure in the order non-object, name control char (`malformed_control_dropped`), name bad (`metric_name_invalid`), value bad (`metric_value_invalid`), baseline present and bad (`metric_baseline_invalid`), direction bad (`metric_direction_invalid`); value and direction both bad counts `metric_value_invalid` only. `metrics_not_list` counts once per item. The item flag stays the generic `metric_invalid`, plus `malformed_control_dropped` for a control char in a metric name.

## LIMITS
Only supplied items are considered. "Breakthrough" means a high computed score on stated criteria, not scientific significance. The report prints the sectors actually covered; nothing is claimed beyond them. NOT implemented: training or modelling (no compute, separate approval), external verification of any claim, fetching or scraping, installing tools.
