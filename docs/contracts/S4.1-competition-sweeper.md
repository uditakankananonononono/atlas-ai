# S4.1 — competition sweeper (c35.sweep) — PARKED

Independent module; additive.

## What the code does

`backend/app/modules/c35/sweep.py`, stdlib only (`re`, `datetime`, `app.modules.c30.policy`), deterministic (sorted keys, no wall clock except the caller-supplied `as_of`).

- `run(request)` — checked FIRST, before any parsing: always raises `APPLY_REFUSED_PARKED` while the module constant `PARKED = True` stands, whatever the input (including a key `unparked`). No request field, env var or flag lifts the gate; it changes only by a reviewed code change carrying a pinned, host-verified owner-channel instruction.
- `build_dossiers(request)` — pure builder, importable for tests and prep; never reached through `run()` while parked. Request: `{as_of: YYYY-MM-DD, sources: [{id, kind, text, url?}]}`, `kind` in `bookmark_doc|starred_mail|social_save|public_page|private_third_party` (private refused). Extracts per supplied source: deadline (first ISO `YYYY-MM-DD` candidate, else first `Month D, YYYY` candidate; unparseable candidate → `deadline: null` + flag `deadline_unparsed`; no candidate → flag `no_deadline`), fee (`free` keyword first, else `USD|EUR|GBP n` or `$n` verbatim), eligibility lines (grade/age/years old/country/citizen/resident keywords). Assembles dossier sections `rules`, `past_winners`, `judging_criteria` as verbatim lines with `{source_id, offset (char), text}`; an empty section is the string `not_in_sources` (never invented). Deadline `< as_of` → status `expired`; `== as_of` is NOT expired; no deadline → `undated`. Duplicate opportunities across sources merge by key (title casefolded + whitespace-collapsed, ISO deadline or `''`); merged `source_ids` sorted. Output `{as_of, parked, opportunities (sorted by folded title + deadline), coverage{sources_supplied, with_deadline, with_fee, expired}, scope}`. No ranking, no prefill, no waiver templates, no link indexing, no EV.

## Refusal table

All refusals are `ValueError` with message `APPLY_REFUSED_<REASON>[:field]`:

| Message | When |
|---|---|
| `APPLY_REFUSED_PARKED` | any `run()` call while PARKED |
| `APPLY_REFUSED_BAD_TYPE:request` | request not exactly a dict (subclasses refused) |
| `APPLY_REFUSED_BAD_TYPE:key` | a request or source key is not exactly `str` (previously a bare TypeError) |
| `APPLY_REFUSED_UNKNOWN:<key>` | unknown top-level or source key (incl. `unparked` in build_dossiers) |
| `APPLY_REFUSED_BAD_TYPE:as_of` | as_of not ISO `YYYY-MM-DD` or not a real date |
| `APPLY_REFUSED_NOSOURCE` | sources missing, not exactly a list (subclasses refused), or empty |
| `APPLY_REFUSED_OVERSIZE` | >200 sources, or >2,000,000 total source-text chars |
| `APPLY_REFUSED_BAD_TYPE:source` | a source is not exactly a dict (subclasses refused) |
| `APPLY_REFUSED_SUBMIT` | any source key matching submit/submission/apply/password/token |
| `APPLY_REFUSED_BAD_TYPE:kind` | kind outside the allowed set |
| `APPLY_REFUSED_PRIVATE` | kind `private_third_party` |
| `APPLY_REFUSED_TEXT_TOO_LONG:text` | one source text over 200,000 chars (clean_text's own name, unremapped) |
| `APPLY_REFUSED_BAD_TYPE/EMPTY/CONTROL_CHARS/TEXT_TOO_LONG:<field>` | clean_text's own codes for id (128), url (512), title (200), text |

## LIMITS

200 sources max; 2,000,000 total text chars; 200,000 chars per source text; id 128 chars; url 512 chars; title 200 chars. Deadlines: first candidate wins; `Month D, YYYY` English month names only. Fees: `free` keyword outranks currency match; first fee found per opportunity wins. Section/eligibility matching is per-line keyword regex, verbatim output.

## Pure-offline applicability note

The unit handles competition material, so these standing rules apply; each is met by having NO code path rather than by a check:

1. Never fetch / no network: module imports only `re`, `datetime` and `c30.policy`; no socket/urllib/http import or call exists.
2. Never log in: no credential, session or auth concept exists; private third-party sources are refused (`APPLY_REFUSED_PRIVATE`).
3. Never apply or submit: any submit/submission/apply/password/token field in a source dict is refused (`APPLY_REFUSED_SUBMIT`); the module builds dossiers only.
4. No spend: no price, payment or purchase concept exists.
5. No outreach: no send/message/contact concept exists.
6. run() is not a parked-run surface: `run()` raises PARKED before parsing for every input; the only callable surface is pure `build_dossiers`, proven by `test_scope_block_and_no_effect_surface` (the module exposes exactly `run` and `build_dossiers` of its own) and `test_run_parked_first_even_for_garbage` (garbage, empty, and `{'unparked': True}` inputs all refuse PARKED).

## S4.2 / S4.5 interface comparison

The comparison below concerns supplied-data interfaces, not live service availability.

- S4.2 `docs_ingest`: document indexer — `index[{url normalized, label, kind in scholarship|competition|grant|admissions|job|unknown, doc_urls}]`, `waiver_templates[{text, placeholders, doc_url}]`, `coverage{links_found, duplicates_dropped, unknown_kind}`. Supplied pinned docs only; no fetch, no live verification, no deadlines. Disjoint from S4.1: S4.1 never classifies links and never touches waiver templates; S4.2 has no deadline/fee/eligibility/dossier/expiry concepts. Schemas share no keys.
- S4.5 `prefill`: preparation/ranking — `packets[{id,title,filled,missing_fields,draft_required}]`, `tracker[{id,title,deadline,days_left,status}]`, `ranking{ranked by score = value*p_win/effort_hours, unranked}`, `calendar`, `scope`. S4.1's `{title, ISO deadline}` is the natural upstream feed for S4.5's tracker/ranking, but S4.1 emits no id field (opportunities are dedupe-keyed), no days_left, no score, no packets, no calendar. Expiry semantics agree: `deadline == as_of` is NOT expired in both; S4.5 still ranks expired items, S4.1 only marks and counts them.
