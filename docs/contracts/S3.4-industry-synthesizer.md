## Input contract

Required keys: `taxonomy`, `touched`, `needs`, `capabilities`, `min_gap_severity`. Optional keys: `as_of`, `coverage_assertion`. Unknown keys refuse, including instructions to submit or spend. No field can grant effect authority.

- `taxonomy`: nonempty list of exactly `{code, name, parent}`. Parent is null or a known code. Codes are unique; cycles refuse. Multiple roots and uneven depths are supported.
- `touched`: list of exactly `{code, unit_id, evidence}`. Code must exist. Evidence is caller-supplied text, not independently verified. Multiple references are preserved but cannot double-count a code.
- `needs`: list of `{id, text, codes, severity, evidence_url?}`. IDs unique, codes nonempty/unique/known, severity a finite number in [0,1], not bool. Missing/blank evidence URL excludes a need only from candidate generation, not coverage or gap ranking. A URL is never fetched or authenticated.
- `capabilities`: list of exactly `{id, text}`, IDs unique.
- `min_gap_severity`: finite number in [0,1], not bool.
- `as_of`: supplied text; default `supplied-input`. No wall-clock reads.
- `coverage_assertion`: exactly `{word, coverage_percent}`. Word is `all`, `every` or `covered`; finite percentage in [0,100], not bool, must equal the computed overall rounded percentage. It asserts the supplied taxonomy percentage only, not global coverage. The assertion schema is a design choice, not owner wording.

Design limits: taxonomy 1,024 rows; needs 1,024; capabilities 256; touched references 4,096. Code, parent, IDs and as_of max 128 characters; taxonomy names max 256; need/capability text, evidence and evidence_url max 2,048. Text validation is canonical `policy.clean_text`, including Unicode control character refusal. Caps are inclusive. Supplied lists/rows are not mutated.

## Coverage and gaps

A code is touched if directly touched or if any descendant is directly touched. Ancestors roll up. Direct touching of an ancestor does not touch descendants. Leaf coverage uses directly touched leaves only.

`levels` groups by root-relative depth. Each includes touched, total and coverage_percent rounded to one decimal. `ancestor_coverage` is a design choice: for each nonleaf ancestor, count rolled-touched nodes in its entire subtree, including itself, divided by subtree node count. `coverage` counts rolled-touched nodes divided by all supplied nodes. Direct/rolled code lists, retained touched references and untouched code rows are also returned. Untouched rows sort by descending supplied need count, then code; every need counts regardless of severity/source, once per attached code.

A need is a gap when severity >= threshold and any attached code remains untouched after rollup. Partial gaps list touched_codes and untouched_codes. Fully untouched needs are open_gap; fully touched needs are excluded. Score = severity x untouched-code count / total-code count, rounded to six decimals. Sort descending score then ID. All output floats round to six decimals; coverage percentages retain their one-decimal computation. Sorting uses raw score before canonical serialization. No implied need discovery.

The 60-node fixture has 5 roots, 15 groups, 40 leaves and 15 directly touched leaves. Coverage is 5/5 = 100%, 15/15 = 100%, 15/40 = 37.5%; overall 35/60 = 58.3%. Its 20 needs produce 15 partial gaps and 5 fully open gaps.

## Candidate drafts and lexical check

Only source-bearing eligible gaps are paired with capabilities. This is an explicit interpretation of the generic pair-generation wording: closed needs, below-threshold needs and source-less needs are not candidates.

Tokenizer: lowercase, ASCII regex `[a-z0-9]+`, unique term set. No stemming, synonyms, Unicode word segmentation or semantic similarity. Fixed stopwords:

`a an the and or of to in on for with is are was were it its by from as at be this that`

Relevance requires a nonempty intersection between need and capability content terms, emitted as `shared_terms`. Name template is `{need text} / {capability text}`; `key_terms` is the content term set of that exact name. Draft status is separate metadata, not a token silently excluded from the name.

Compare key_terms to every taxonomy name's content term set. A match requires both sets nonempty and full-set containment in either direction. One shared term alone does not match. A matching draft is omitted from `candidates` and retained in `omitted_candidates`, with code `OVERCLAIM` and all matched taxonomy codes. This does not refuse the whole request.

Each record includes need_id, capability_id, supplied codes, evidence_url, name, shared_terms, key_terms, kind `keyword_recombination_draft`, novelty_verified false, industry_created false and physical_execution false. This is a lexical taxonomy check, never a claim that a real new industry exists. Source-less needs appear in excluded_candidate_needs with `PROTO_REFUSED_NOSOURCE`. Candidate records sort by need ID then capability ID.

## Refusals

Refusals raise ValueError, never return success-like error dicts.

| Prefix/reason | Meaning |
| --- | --- |
| `PROTO_REFUSED_NOTAXONOMY` | Empty/invalid taxonomy container |
| `PROTO_REFUSED_NOTAXONOMY:duplicate/parent/cycle` | Invalid hierarchy |
| `PROTO_REFUSED_NOTAXONOMY:touched_code/need_code` | Unknown referenced code |
| `PROTO_REFUSED_BAD_TYPE:<field>` | Invalid type, field set, range, duplicates or row-size cap |
| `PROTO_REFUSED_EMPTY:<field>` | Blank required text or empty need codes |
| `PROTO_REFUSED_CONTROL_CHARS:<field>` | Canonical text hygiene refusal |
| `PROTO_REFUSED_TEXT_TOO_LONG:<field>` | Canonical text limit refusal |
| `PROTO_REFUSED_OVERCLAIM` | Caller coverage assertion differs from computed supplied-taxonomy percentage |

`NOSOURCE` is a per-need candidate disposition, not a whole-request failure. Candidate `OVERCLAIM` is a per-draft omission. Neither means authenticating source contents.
