# S5.6 Virtual world and AI people sim (c36.world, prefix VENT)

A seeded, deterministic toy simulation of SUPPLIED synthetic characters in a SUPPLIED small world. It returns an event log and a text-only storyboard draft. Entry point: `app.modules.c36.world.run(request)`. Pure stdlib plus `app.modules.c30.policy` (`clean_text`, `scope`); no network, no files, no clock, no `random` module.

## LIMITS
- Toy simulation: each character picks a place and an action by pseudo-random draw. There is no behavior model, no dialogue, no physics.
- No real-person check. The unit does not match names or traits to real people and cannot tell whether a supplied name resembles one. Supplying likeness-related input is refused by key name only; values are never scanned.
- No media generation: output is text only (event records and storyboard frame text with a `TO_WRITE: voiceover` placeholder).
- Nothing is published, posted, sent, paid for or uploaded. The module exposes one function, `run`.
- Every agent record, event and frame is labeled `SYNTHETIC-AI`. No input field can turn the label off or change it.

## Input
```
{as_of: "YYYY-MM-DD", seed: int 0..4294967295,
 world: {name, places: [str], steps: int 1..100},
 agents: [{id, name, traits: [str], actions: [str]}],
 scenario: {kind: "commercial_storyboard" | "daily_life", product: str}}
```
Allowlists (any other key is refused): top `as_of seed world agents scenario`; world `name places steps`; agent `id name traits actions`; scenario `kind product`.

## Caps (each N accepted, N+1 refused as OVERSIZE:<field>)
agents 50; id 64; agent name 100; traits 10 and actions 10 per agent, each item 64; places 30, each 100; world name 100; steps 100; seed 4294967295; product 200; as_of 10 (raw length, checked before the date grammar); scenario kind 64 (raw, see below). The shared text helper's own length code never surfaces: every text cap is checked first with the same limit.

## Validation order
1. request is exactly a `dict`. 2. Forbidden-key scan (below), recursive over dict values and list/tuple items. 3. Non-str key. 4. Unknown key at any level (`UNKNOWN:request|world|agents|scenario`; unknown kind value is `UNKNOWN:kind`). 5. Top-level types: `as_of` a real calendar date (year at least 1, leap years honored), `seed` and `steps` exact ints (bool refused), empty agents or places, empty traits or actions. 6. Caps. 7. Per-field validation in list order through `clean_text` (single-line; control, format, line and paragraph separators refused). 8. Compute.

## Forbidden keys
Keys are normalized (casefold, `-` to `_`) and matched exactly at any depth. Precedence SEND > SPEND > DECEPTIVE > EFFECT > NOCREDS; within a class the alphabetically first matched table key is the suffix. Values are never scanned.

| Class | Keys |
|---|---|
| SEND | send approve approved approval approval_token smtp token email_send sender smtp_host smtp_port smtp_user |
| SPEND | pay purchase spend buy checkout card_number |
| DECEPTIVE | real_person likeness impersonate deepfake voice_clone endorsement testimonial celebrity |
| EFFECT | publish post upload deploy broadcast advertise |
| NOCREDS | login password username credentials otp api_key access_token refresh_token bearer pass passwd |

## Refusals
Every refusal is `ValueError("VENT_REFUSED_<REASON>[:field]")` and never echoes input content.

| Code | When |
|---|---|
| BAD_TYPE:request | request not an exact dict, or any dict/list/tuple subclass or str-subclass key found anywhere |
| BAD_TYPE:key | non-str dict key (after the forbidden-key classes) |
| BAD_TYPE:<field> | wrong type or missing: as_of, seed, world, agents, scenario, world_name, places, steps, kind, product, id, name, traits, actions; seed or steps below range; duplicate agent ids (`agents`); duplicate places after casefold (`places`) |
| EMPTY / EMPTY:name | no agents, places, traits or actions / blank name |
| OVERSIZE:<field> | a cap above is exceeded |
| OVERSIZE:request | scan budget exceeded (below) |
| UNKNOWN:<level> / UNKNOWN:kind | unknown key / kind not in the two allowed |
| SEND / SPEND / DECEPTIVE / EFFECT / NOCREDS : <key> | forbidden key |

## Request scan budget
The scan accepts exact builtin `dict`, `list`, `tuple` containers and exact `str` keys only. Checks run on a container before it is iterated: at most 10000 distinct containers (an object reachable twice counts once), 32 keys per dict, 64 items per list or tuple, depth 32 (request = 0), key length 200 characters measured raw before any normalization. A subclass of dict, list, tuple or str is refused `BAD_TYPE:request` before it is read or any of its methods is called. Over-budget is `OVERSIZE:request`, ahead of every content refusal and every forbidden-key class. The list cap of 64 lets the schema `OVERSIZE:agents` (51 to 64 agents) fire first. These numbers are this unit's choices, not spec values.

## Scenario kind (enum admission order)
For exact str, the raw cap then membership run in the unknown-key stage: a value longer than 64 characters is refused as `OVERSIZE:kind` before membership; a bounded non-member is `UNKNOWN:kind`. A non-str or subclass kind is refused later in the top-level type stage as `BAD_TYPE:kind` before any kind methods or membership, so other field errors (as_of/seed/world/agents) can surface first. The cap of 64 is this unit's choice, uniform with the identifier caps.

## as_of
`as_of` must be an exact `str` (else `BAD_TYPE:as_of`). Error map: raw length above 10 is `OVERSIZE:as_of`, decided on length alone before the date grammar is looked at; a string of 10 or fewer characters that is not a real calendar date `YYYY-MM-DD` (ASCII digits, month 1..12, day valid for the month and year, year at least 1, leap years honored) is `BAD_TYPE:as_of`. The cap of 10 is the length of the date form, uniform with the program's other date inputs.

## Type before empty
Type refusals for `world.name`, `world.places`, `world.steps`, `scenario.kind` and `scenario.product` run before the empty-agents and empty-places refusal, so a wrong-typed field is always a typed refusal (`BAD_TYPE:<field>`), never `EMPTY`.

## Determinism
Own splitmix64 generator, state initialized to the seed: `state += 0x9E3779B97F4A7C15; z = (state ^ state>>30) * 0xBF58476D1CE4E5B9; z = (z ^ z>>27) * 0x94D049BB133111EB; out = z ^ z>>31`, all mod 2^64. For step 1..steps, for each agent in input order: one draw selects the place (`out % number of places`), the next selects the action (`out % number of the agent's actions`). Same input gives byte-identical output (checked with sorted keys) across Python versions. The first output for seed 0 is 16294208416658607535.

## Output
`{agents, events, frames, world, coverage{agents, steps, events, frames}, scope}`. Event: `{step, agent_id, place, action, label, ai_generated}`. Frame: `Frame N [SYNTHETIC-AI] <name> at <place>: <action>. Product: <product>. TO_WRITE: voiceover` (the product sentence appears for `commercial_storyboard` only; for `daily_life` a supplied product is accepted, capped and not rendered).

## Choices not fixed by the spec (disclosed)
as_of cap 10 (raw length before the date grammar); steps or seed above range is OVERSIZE, below range or non-int is BAD_TYPE; `product` required for commercial_storyboard, optional for daily_life; the scan numbers; `world` echoed in the output; `kind` of the wrong type is BAD_TYPE:kind.
