# c30.x_register - v2 X1-X30 cannot-as-stated register: bounded substitutes

Source pin: AGI mega-spec build program v2, section 1 "Cannot-become-code-as-stated register (each has a substitute)" rows X1-X17 and section V2-2 rows X18-X30. Program rule verbatim: "Honesty rule: each report carries a `scope` block: `{implemented, not_implemented, data_source, as_of}`. No output may claim coverage ("all", "every") the input did not have. Coverage numbers are computed, not asserted."

Modules: `backend/app/modules/m20_general_cognitive_worker/c30/x_register.py` (30 substitutes). There is no local policy module: the standing-rule refusals and text hygiene use the canonical `app.modules.c30.policy` (`check`, `clean_text`) with the prefix `XREG`. Pure stdlib, deterministic, fully offline. No clock, randomness outside x12's seeded generator, I/O, filesystem or network. No wiring: no routes, no registration.

## Guard (canonical c30.policy)
Every substitute calls a local `guard(payload)` first. It holds a 13-key table (`FORBIDDEN_KEYS`) that maps a supplied request field to a canonical rule name, and it calls the canonical `app.modules.c30.policy.check(rule, "XREG")` when that field is truthy. The result is the canonical refusal `XREG_REFUSED_<RULE>`: spend/purchase/buy_compute -> `XREG_REFUSED_SPEND`; send/submit/outreach -> `XREG_REFUSED_OUTREACH`; multi_account/fake_accounts -> `XREG_REFUSED_FAKEACCT`; post_now/autopost -> `XREG_REFUSED_AUTOPOST`; scrape -> `XREG_REFUSED_SCRAPE`; broker/live_trade -> `XREG_REFUSED_TRADE`. The table's rule names are pinned by a test against the canonical `RULES`. The guard only ever refuses; it permits nothing. A falsy forbidden key is not in any function's field set and fails shape strictness instead (documented order: policy guard, shape, semantics). The canonical policy is not edited by this module.

## Shared validation
Every payload is a dict with exactly the named required fields plus documented optional action flags (unknown -> `XREG_REFUSED_UNKNOWN_FIELDS:<where>`, missing -> `XREG_REFUSED_EMPTY_FIELD:<name>`; a blank text value is `XREG_REFUSED_EMPTY:<name>`). Text fields go through the canonical `clean_text`: type `XREG_REFUSED_BAD_TYPE:<name>`, raw length `XREG_REFUSED_TEXT_TOO_LONG:<name>`, blank `XREG_REFUSED_EMPTY:<name>`, Unicode Cc/Zl/Zp/Cf `XREG_REFUSED_CONTROL_CHARS:<name>` (checked in that order). Integers are exact-type (bool and subclasses refused) as `XREG_REFUSED_OUT_OF_RANGE:<name>`; numbers refuse bool/NaN/inf as `XREG_REFUSED_BAD_TYPE:<name>`. List caps refuse as `XREG_REFUSED_OVERSIZE:<name>`; duplicates as `XREG_REFUSED_DUPLICATE:<name>`. Every result carries `scope: {implemented, not_implemented, data_source: "supplied", as_of}` with as_of echoed from the required payload field.

Shape policy: containers are read as exact built-ins only. A payload, record, mapping or list that is a subclass of dict or list is refused with the same code as any other wrong shape (`BAD_TYPE:<where>`, `BAD_TYPE:axis_pair`, or `OVERSIZE:<name>` for list/mapping fields); a record key must be an exact `str` (`BAD_TYPE:key`). A record with more than 64 keys is refused `OVERSIZE:<where>` before any key is read (the 64 is this module's own bound). Length caps are checked before iteration. Mapping keys for x06 profile, x20 axes and x22 fields/profile must be exact `str`, refused in declared order before any conversion or sort (`BAD_TYPE:profile_key`, `BAD_TYPE:axis_key`, `BAD_TYPE:field_key`); x20 pair keys likewise (`BAD_TYPE:axis_pair`). Values are not coerced: an x22 field or profile value that is not a str is refused `BAD_TYPE:value` (previously str() turned 5 into "5"), and x06 profile values were already strict.

## Check order (every function)
policy guard -> payload shape (unknown/missing fields) -> required-field validation in declared order -> register-level semantic refusals -> compute -> scope block.

## Interpretation choices (flagged for review)
- XREG is the refusal prefix for the register (the spec names per-unit prefixes; X rows are not units with routes, so one register prefix is used). Field names, caps (4096 shards, 65536 posts, 256 drafts, 1024 niches, 64 agents, 10000 steps, etc.) and the 0.6 near-duplicate overlap threshold are invented in the family shape.
- Routes are NOT built; functions are the deliverable surface.
- as_of is a required caller-supplied field (no clock) so the honesty block stays deterministic.
- x04 walk-forward checkpoints are clamped to the last index, deduped and sorted (a len<3 series would otherwise index out of range; found by the battery).
- x12 uses random.Random(seed), the only nondeterminism source, fully seeded and reproducible.
- The guard's FORBIDDEN_KEYS vocabulary is the documented trigger surface; forbidden keys are intentionally absent from function field sets so they cannot be smuggled as data.

## LIMITS
Output artifacts only. Nothing here crawls, fetches, sends, submits, posts, files, installs, trades or spends. Counts are computed from supplied input; no "all"/"every" claim is made. The X-register rows remain not-implementable as stated; these are the bounded substitutes, not the aspirations. Passing tests is not audit acceptance.
