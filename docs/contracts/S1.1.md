# S1.1 tool-landscape-scanner (c31.tool_scan)

Source pin (verbatim, spec S1.1): "Has a whole troop of agents inspired but better than Cellcog, strawberry browser and similar tools maybe search up yc companies and replicate them and integrate into atlas".

Does: builds a capability matrix over SUPPLIED tool records (name, license,
price tier, capabilities - e.g. YC directory exports or saved product pages),
sorted by name with deduped sorted capabilities per tool, and computes a gap
list: capabilities present in the landscape but absent from the caller's
supplied atlas-module list.
Does not: crawl anything live, or install or buy any tool; purchase=True
routes through the c30 spend guard and refuses. "Daily" cadence from the spec
is the caller's scheduler, not this unit - one call is one scan of supplied
input.
Refusals: FLEET_REFUSED_NOSOURCE (tools missing/not a list/empty) /
OVERSIZE (>4096) / BAD_TYPE:tool|capabilities|atlas_modules /
DUPLICATE:<name> / BAD_LICENSE:<license> (not in mit|apache|bsd|gpl|proprietary|unknown) /
BAD_PRICE_TIER:<tier> (not in free|freemium|paid|unknown) /
plus c30 clean_text codes BAD_TYPE/EMPTY/CONTROL_CHARS/TEXT_TOO_LONG on
name, capability, atlas_module (<=128 chars) and POLICY_REFUSED_SPEND via the guard.
Limits: MAX_TOOLS 4096; deterministic sort by name; capabilities deduped.
IC: gap list is set difference vs the caller-supplied module list, not a
live registry lookup.
