## What the code does

Both modes are pure functions of the request. The only date is the `as_of` input (ISO YYYY-MM-DD). No clock, no network, no files.

- `mode: checklist`: each requirement becomes `done` or `missing`. Key = requirement text, stripped, casefolded, whitespace runs to `_`;
  done iff that exact key is in `profile` with a value that is not None, `""` or whitespace-only. `prefill` holds the done values
  (sorted keys, floats rounded to 6 places). Requirements whose key is a credential or government-ID key (`password login username otp ssn passport aadhaar pan national_id card_number`)
  get status `prefill_excluded`: they are never counted done or missing, never prefilled, their profile value is never output, and they are listed in `prefill_excluded`.
  `coverage` = `{done, missing, prefill_excluded}` counts (`done_count` and `missing_count` repeat the first two). `days_left = (deadline - as_of).days`, negative when past, with `status` `expired`; 0 on the deadline day is `open`.
  `olympiad.fee`, if supplied, is ignored and never output.
- `mode: mock`: `score = round(correct/total, 6)`; unanswered or blank answers count wrong. Compare: strip both sides, exact match; case-insensitive only when both
  stripped sides are one alphabetic character. `per_tag` counts a multi-tag question under each tag (tag totals can exceed the question total, stated in `tag_note`);
  duplicate tags in one question count once; untagged questions go under `untagged`. `over_time` is `elapsed_s > time_limit_s` (equality is not over); the score is still reported.
  Answer ids not in the bank are ignored and listed in `unknown_answer_ids`. Prompts are never echoed.
- Every success carries `scope` from `policy.scope` and a `limits` string.

## Refusals (all raise `ValueError("APPLY_REFUSED_<REASON>[:field]")`)

| Reason | When |
|---|---|
| SEND | key in: send approve approved approval approval_token smtp token email_send sender smtp_host smtp_port smtp_user |
| SPEND | key in: pay waive_fee fee_action |
| REGISTER | key in: register submit |
| ATTEMPT | key in: attempt take_exam |
| NOCREDS | key in: login password username credentials otp api_key access_token refresh_token bearer pass passwd |
| BAD_TYPE | wrong type or format (request, key, mode, as_of, deadline, olympiad, requirement(s), profile, bank, id, tags, answers, answer, time_limit_s, elapsed_s); duplicate bank ids; a non-str dict key at any depth (`BAD_TYPE:key`, after the str-key scan so a forbidden key still wins); a profile value that is not str, int, finite float, bool or None (`BAD_TYPE:profile`); a non-str `mode` (`BAD_TYPE:mode`) |
| EMPTY | empty bank, requirements, or blank text field |
| OVERSIZE | more than 256 bank items, 64 requirements, or a prompt over 2000 characters |

Forbidden keys: scanned recursively over dict KEYS at any depth (through lists), casefold plus `-` to `_`, exact match (no substrings); values are never scanned.
The whole request is refused before any other validation.
Check order: dict, then forbidden-key scan, then non-str key, then top-level types and `mode` (`as_of`, `mode`, then `olympiad`/`requirements`/`profile` or `bank`/`answers`), then caps (EMPTY, OVERSIZE incl. prompt length), then per-field checks, then compute. Precedence SEND > SPEND > REGISTER > ATTEMPT > NOCREDS; within a class the first matched table key in sorted order. The suffix is that normalized table key (e.g. `APPLY_REFUSED_NOCREDS:login`, `APPLY_REFUSED_SEND:approval_token`); no request-derived path, key text or value ever appears in a reason.
`mode` is a str type check, then an exact compare (no trim, no casefold, no length cap, never `clean_text`). An unknown `mode` string, including `""`, whitespace and control-character strings, fails closed with `APPLY_REFUSED_UNKNOWN:mode` (the suffix is the field name, never the untrusted value); a mode that is itself a standing-rule name (`spend`, `outreach`, `fakeacct`, `autopost`, `scrape`, `trade`) goes to `policy.check` and refuses with that rule code, e.g. `APPLY_REFUSED_SPEND`.
Naming note: S4.3 maps register/submit/attempt to SUBMIT; S4.8 deliberately maps them to REGISTER and ATTEMPT. The key list is a bounded list, not a security proof.

Limits: `time_limit_s` finite number, not bool, 0 < x <= 86400; `elapsed_s` finite, not bool, 0 <= x <= 604800.

## Pure-offline applicability note (c30 standing rules)

Of the six rules (spend, outreach, fakeacct, autopost, scrape, trade) none has a code path here: the module imports only `datetime`, `math`, `re` and `app.modules.c30.policy`,
defines no function other than `run` as public, and does not register, log in, attempt a real exam, pay, send, post, trade or create accounts. A test asserts the public surface and the import set.
These are static checks: they show the module defines no such function and imports no such library. They are not sandbox proof and not a security claim.
Any future external action needs the owner's explicit yes, which no input field can supply.

## LIMITS

A mock score is not an olympiad score. The unit supplies no question content (test fixtures are synthetic arithmetic, no claim of olympiad validity). It does not claim readiness.
Not covered: real registration, login, payment, sending, deadline timezones, localised date formats, profile value shapes beyond str/int/float/bool/None.
