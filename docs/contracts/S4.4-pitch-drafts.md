# S4.4 journal-and-org-pitch-drafts (`/c35/pitch-drafts`, prefix APPLY)

## Honest scope (read first)
This is a **prototype of a draft-and-queue mechanism**. It is not a model, not autonomous, and **nothing is ever sent**.
There is no send, submit, network, file, clock or random code path. A "release" returns a packet that the owner sends by hand.
Fit scores are computed from supplied inputs against declared conditions. They do not judge whether the research is good, and do not predict acceptance.

## Admitted publication fragments (data only)
- Unit: `S4.4`, implementation `pitch_drafts`.
- "sends research to reputed journals, with my approval"
- "short pitches to organisations maybe like nasa, or non profits, cern etc. with my permission"
- pin offsets recorded in the private ledger
- This library computes checklist fit and prepares reviewable packets.
- No communication capability is implemented here.

## What the code does
1. `score_fit(guidelines, manuscript)`: five weighted checks (scope 3, length 2, format 1, sections 2, fee 1; total 9). Score = `points*100//9`. Verdict `FIT_CONDITIONS_MET` (all pass), `PARTIAL` (score >= 50), `LOW_FIT`. Carries an always-false honesty block.
2. `make_journal_draft(target, manuscript, author, fit)`: cover letter from a fixed template. Verifies the fit object against the manuscript (hash plus recomputed score). Refuses `LOW_FIT`.
3. `make_org_pitch_draft(target, author, ask)`: short pitch from a fixed template, at most 200 words.
4. `queue_add(queue, draft)`: functional (returns a new list), max 50, no duplicates.
5. `release(queue, approval)`: needs an approval naming the exact draft id, recipient and sha256 of recipient+subject+body, with `approved_by == "owner"`. Returns `(new_queue, packet)`; the packet says `OWNER_SENDS_MANUALLY`. Single use.

## Refusal codes
`APPLY_REFUSED_SEND` (no or mismatched approval, unknown draft, already released), `APPLY_REFUSED_BULK` (more than one recipient), `APPLY_REFUSED_NOSOURCE` (guidelines lack an https source or a valid as_of date). Everything else is `pitch_drafts:<reason>` and never echoes input.

## INTERPRETATION CHOICES (not pinned by the spec)
1. INTERPRETATION CHOICE: check weights 3/2/1/2/1 and the PARTIAL cut-off at 50.
2. INTERPRETATION CHOICE: scope passes when keyword overlap >= min(2, number of distinct manuscript keywords) and > 0; case-insensitive exact keyword match, no stemming.
3. INTERPRETATION CHOICE: `LOW_FIT` journals get no draft (`pitch_drafts:low_fit`).
4. INTERPRETATION CHOICE: the approval token is a binding of draft id, recipient and text hash, plus the literal `"owner"`. The spec pins "exact-draft approval" but no token shape.
5. INTERPRETATION CHOICE: release returns a manual-send packet and marks the item `APPROVED_FOR_MANUAL_SEND`; there is no `SENT` state at all.
6. INTERPRETATION CHOICE: one recipient only per draft; `,` or `;` gives `APPLY_REFUSED_BULK`. The owner supplies every recipient address; the code never discovers one.
7. INTERPRETATION CHOICE: pitch cap of 200 words ("short" is unpinned); queue cap 50; keyword list cap 50; string cap 200 (summary 1200).
8. INTERPRETATION CHOICE: the "not under review elsewhere" sentence is added only when the owner supplies that flag as true, to avoid inventing claims.
9. INTERPRETATION CHOICE: single-line fields only (no `\n`, `\r`, `\t`); draft bodies get their line breaks from the template, so the line count is fixed by the template.
10. INTERPRETATION CHOICE: unknown approval draft id gives `APPLY_REFUSED_SEND`, not a separate code.

## LIMITS
- `approved_by == "owner"` is a data-integrity string, not owner authentication. The approval token is a binding of draft id, recipient and text hash; nothing here proves the owner made it. The integrator must create it only from her actual approval message.
- Fit uses only supplied guideline data; nothing is fetched. `as_of` is checked for shape, not freshness.
- No semantic check of the manuscript, no check that the target journal or organisation is reputed, no deliverability or address verification.
- Fee fit compares numbers; it never pays anything (spend stays refused elsewhere).
- Not wired to any route or the c30 policy guard; the integrator owns wiring.
- The module is `app.apply.pitch_drafts`; the `c35` module path in the spec is not present on main.

## Mutation battery
AST battery over every comparison, boolean operator, bool/int/string constant: 516 sites, 511 mutants run. First pass 132 survivors, but that pass had a stale `.pyc` problem (same-size mutants reused cached bytecode); I fixed the program (`PYTHONDONTWRITEBYTECODE=1`) and the first pass is kept only as `mutation_run1_stale_pyc.json`. Second pass with 47 tests: 30 survivors. After the pins: 9 survivors, each argued equivalent:
1. `'\n\r\t'` -> `'\n\r\t~'` (`_TEXT_WS`): `~` is not a forbidden category, so allowing it changes nothing.
2. `score >= 50` -> `> 50` and `50` -> `51` (`_verdict`): possible scores are `points*100//9`: 0,11,22,33,44,55,66,77,88,100. None lies in 50..55, so the cut-off is not observable.
3. `len(addr) > 254` -> `>= 254` and `254` -> `255`: dead only for the builders, where `_str` refuses anything over 200 characters first. On the public direct queue schema (`queue_add`, `release`) the guard is live (a 255-char recipient gives `bad_recipient`, a 201..254-char one gives `bad_draft`) and is pinned by `test_recipient_254_guard_is_live_on_public_queue_schema`; after the repair these two mutants are killed.
4. `_scan(d, "queue", 0, ...)` depth 0 -> 1: a draft is flat, depth is never near the limit of 6.
5. `overlap > 0` -> `>= 0`: the manuscript keyword list has at least 1 distinct keyword, so `overlap >= min(2, len(mk))` already needs overlap >= 1.
6. `s[8:10]` -> `s[8:11]`: the string is exactly 10 characters, so the slice is identical.
7. `'utf-8'` -> `'utf-8~'`: Python normalizes the codec name and resolves it to utf-8 (checked).
Counted as 9 mutants (items 2 and 3 are two each).
Full per-mutant record (original and mutated expression, status, killer) is in `mutation.jsonl`.

## Repair (audit: public queue bypass)
- Finding: `queue_add` took a hand-built draft (for example recipient `one@example.org,two@example.org`, hash recomputed by the caller), and `release` could output a bulk packet, bypassing the builder gates. Raw TypeErrors also leaked on non-string fields.
- Fix: one shared `_check_draft` validates every draft at `queue_add` (status DRAFT) and for every stored entry at `queue_add` and `release` (status QUEUED or APPROVED_FOR_MANUAL_SEND): exact keys, string types (`pitch_drafts:bad_type:draft`), kind, status, `sent is False`, single recipient (`APPLY_REFUSED_BULK` or `bad_recipient`, at most 200 chars), subject 1..300, target name 1..200, body 1..5000 chars, word caps (org pitch 200, journal 1000), exact sha256 and draft id. Queue length at most 50, no duplicate ids in a stored queue.
- INTERPRETATION CHOICE 11: caps for journal words (1000), body chars (5000), subject (300); a tampered stored entry now fails with `pitch_drafts:bad_draft` instead of `APPLY_REFUSED_SEND` (it never reaches the approval comparison).
- Test edits after the repair red commit: `test_release_edited_text_invalidates_approval` and the three stored-item tamper cases in `test_release_messages_and_order` now expect `pitch_drafts:bad_draft`, because shape validation runs first. The refusal is still a PitchRefusal; the edited text can still not be released.
- Audit addition: the `_scan` leaf guard (floats, tuples, bytes, sets, other objects) is pinned on the public surfaces (draft fields, stored queue entries, fit fields, approval fields) with the exact `bad_type:queue|fit|approval` messages.

## Mutation result after repair
555 mutants run over 561 sites. Pass 1 left 13 survivors: 6 were real (the literal values of the three public-schema caps, which the tests read from the module itself, and the three `0 <` minimum-length guards); they are now pinned with literal limits and one-character fields. A first run of this battery was void because the isolated copy lacked the docs file the doc test reads, so every mutant "died" on that; that file is kept as `invalid_run_stale_docs.json` and not counted. Remaining 7 survivors are argued equivalent: `_TEXT_WS` + "~"; `score >= 50` vs `> 50` and `50` vs `51` (scores are only 0,11,22,33,44,55,66,77,88,100); queue scan depth 0 vs 1 (a draft is flat); `overlap > 0` vs `>= 0` (implied by `overlap >= min(2, len)` with at least one keyword); `s[8:10]` vs `s[8:11]` on a 10-character string; `'utf-8~'` (normalized by Python to utf-8). The 254 recipient guard is NOT among them (see above, it is live on the public schema and killed).
