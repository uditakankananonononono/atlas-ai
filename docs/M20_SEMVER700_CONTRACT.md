# M20 SEMVER700 scoped contract

Finite caller-supplied API signature snapshot diffing only. Each snapshot declares 0..1024 function symbols; a symbol has a unique name of 1..200 chars, kind `function` (the only supported kind), and a signature of 0..64 params plus a declared return type string of 1..200 chars. A param has a unique-per-symbol name of 1..200 chars, kind `positional` or `keyword`, a boolean `required`, and a declared type string of 1..200 chars. Unknown keys, duplicate names, wrong types and bound violations refuse with E_SCHEMA. Inputs are declarations, not observed runtime truth.

The diff is structural. A symbol present only in the baseline is breaking (`removed`); only in the candidate, additive (`added`). For a symbol on both sides: positional params are an ordered calling convention, so a name mismatch at any shared position, a removal, an inserted or appended required positional, a required-tightening, or a type change is breaking, while an appended optional positional or a required-to-optional widening is additive. Keyword params match by name: a removal, an added required keyword, a required-tightening or a type change is breaking; an added optional keyword or a widening is additive. Any declared return-type change is breaking; no subtyping analysis is attempted. A kind change is treated as removal plus addition. A symbol with no effective change is `identical`. Any breaking element makes the whole diff `breaking`; else any additive element makes it `additive`; else `no-public-change`. Per-symbol classes, exact change-detail strings and counts are reported, sorted by symbol name, deterministically, independent of input order; identical inputs give byte-identical output.

The recommendation is exact arithmetic on the current version, parsed as strict semver 2.0.0 (leading zeros and malformed shapes refuse with E_VERSION_PARSE; components are bounded to 2^53-1 for exactness, N+1 refuses). Breaking recommends a major bump, additive a minor bump, no-public-change a patch bump; a breaking diff never yields a patch or minor recommendation, and a bump that would exceed the component bound refuses with E_OVERFLOW. Zero-major versions get no special treatment. Prerelease treatment is declared as `development-line-core-bump`: prerelease and build metadata are stripped, the recommendation is the next stable version computed from the stable core, and no prerelease progression is managed.

Caller change labels (overall and per-symbol) are accepted as claims, validated, and echoed as `label_conflicts` when they disagree with the structural result; they never influence the classification or the recommendation. Unknown label values or labels for unknown symbols refuse with E_SCHEMA.

This is a restricted computation over declared API shapes, not a runtime compatibility proof, a changelog, a release decision or publishing. No network, persistence, repository mutation or installation. Mounted authentication and tenant boundaries apply after integrator wiring; the wiring patch is separate and unapplied.
