# A08: real Celery worker and Redis result transport

Source: technical-spec: "Celery with Redis as broker and result backend".

A separate interpreter imports the Atlas Celery application, suppresses its production include list, registers a test-only echo task, and starts a solo worker listening only on a UUID-scoped acceptance queue. The client submits a JSON payload through Redis, waits for its exact result through the Redis backend, and confirms SUCCESS. It terminates the worker, deletes only the acceptance queue and forgets only its task result. No product task or periodic scheduler runs.

Command: `PYTHONPATH=backend ATLAS_ACCEPTANCE_REDIS_URL=redis://127.0.0.1:16412/0 python -m pytest tests/test_celery_redis_live_acceptance.py`

Observed: 1 passed with Python 3.12.14 and the previously source-built Redis 8.10.2 core executable. The temporary local Redis server was stopped after testing. CI Redis 7 execution is pending. Without a configured URL the check skips; an unreachable configured server fails.

## Boundary

This proves actual Atlas-configured Celery worker execution, JSON transport, and Redis result retrieval for a test-only task. Existing architecture tests separately verify configuration and product task registry. This does not verify any product executor, approvals, scheduling, multiple workers, late-ack redelivery, retry behavior, crash recovery, scaling or production deployment. No live-provider, production-data or complete-backend claim.
