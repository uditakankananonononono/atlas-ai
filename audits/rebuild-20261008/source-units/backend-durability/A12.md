# A12: real Redis Streams adapter acceptance

Source: technical-spec, Message Queue / Event Bus: "Redis Streams for real-time events between services; RabbitMQ optional for complex routing."

Adds a repeatable real-server check of RedisStreamBus. A writer interpreter publishes two events and a separate-stream canary. Fresh reader interpreters replay from the beginning, resume from the first ID, and confirm no events after the second ID. Exact assertions check event payloads and IDs; the separate stream remains isolated. The test creates UUID-scoped keys and removes only those keys, never flushes the server.

Command: `PYTHONPATH=backend ATLAS_ACCEPTANCE_REDIS_URL=redis://127.0.0.1:16412/0 python -m pytest tests/test_redis_stream_live_acceptance.py tests/test_technical_architecture_real_adapters.py`

Observed: 9 passed against the existing locally source-built Redis 8.10.2 core executable, with persistence disabled. Temporary server stopped after testing. No Docker/production service was used. CI has a Redis 7 service and ATLAS_REDIS_URL; its actual execution remains pending publication, so no Redis 7 acceptance claim yet.

The test skips without a configured URL, but fails rather than skips when a configured Redis is unreachable. ATLAS_ACCEPTANCE_REDIS_URL overrides ATLAS_REDIS_URL for isolated acceptance. Existing adapter-suite provider checks are transport fixtures, not provider network calls.
