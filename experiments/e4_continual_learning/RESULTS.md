## Superseded protocol (step 0 draft; not runnable via the Needle 3.0.5 CLI, not a current protocol)
This arm design needs training B on top of an adapter trained on A, which `needle finetune` cannot do (see Step 2). Kept for the record only; the current plan is the Step 2 section that follows.
- Tasks: `gen_tasks.py` writes two disjoint 3-tool sets (A: weather, timer, music; B: email, todo, web search), 4 train and 2 held-out argument values per tool, plus 3 refusal rows each. This is tiny on purpose (15 train rows per set); a run needs more rows and paraphrases or the held-out score will be near 100% or noise.
- Arms: (1) train A then train B, no replay; (2) train A then B with 10% of A mixed in; (3) train A+B jointly (upper bound). 3 seeds. Metrics: held-out exact-match of tool name and arguments on A after B (forgetting), on B, refusal accuracy.
- A result counts only if it exceeds the seed spread, as in the cognition-harness noise study.
- Needs `NEEDLE_TELEMETRY=0` and `DO_NOT_TRACK=1`, per the shared-models privacy guard.

## Step 2 (run 2026-10-12 in a fresh Colab runtime; full logs and row-level outputs retained)
Source pin: atlas-ai 8a79fc4 for the repo; cactus-needle 3.0.5, jax 0.9.0, flax 0.10.7; free T4 (Python 3.13); one seed (the CLI default); 9-row authored test sets A_test and B_test (6 answerable, 3 refusal rows each); exact match of call dictionaries. Run directory `run_20261012T100709Z` (UTC). Retained artifacts: per-command logs, per-query row jsonl for every arm, sha256 of every adapter and archive (bundle `e4-step2-rerun-logs-rows-hashes.tgz` supplied to the review gate; the VM itself is temporary).
Earlier page-read attempt (before this run): the VM disconnected and its logs were lost; those numbers are not used.
Provenance notes. (1) `run_step2.sh` as executed was the version that retried only `finetune` once with an XLA flag and did not record exit statuses; `build` and `eval` were then re-run by separate cells (build2/build3/build4 and eval2/eval3/eval4 logs), so the order of steps is not the script's. Adapter and archive bytes are not in the retained bundle; the sha256 values are text receipts. The script in this patch now retries any failing command once with the flag and uses a timestamped run directory that it refuses to reuse; that new form has been tested only against stub commands, never on Colab. It requires, per arm, a zero final return code from finetune, build and eval, nonempty fresh adapter and archive files, and 18 parseable eval rows, and exits non-zero with SUMMARY FAIL otherwise; stub cases run: all pass; every finetune exiting 1 after leaving an adapter file; every eval exiting 1 after writing 18 rows; one arm's finetune, build or eval failing with a leftover file; base eval failing; finetune failing plain and succeeding on the flagged retry. Each attempt first deletes its own output files so a failed attempt's partial file cannot be counted. (2) The earlier `rm -rf logs art` is replaced by that timestamped directory.
Baseline naming: the "base" arm is the published needle base archive (`needle build` printed "the published base archive", 35.34 MB, sha256 c9d915eca282ed42d1a09b143b592adb4cc6744ffe2d294adf5cfc5548170c38, same hash in two runtimes). Adapter arms are merged onto the `needle3.safetensors` checkpoint. Equivalence of the two was not checked, so arms are compared only against the named published-archive baseline.
